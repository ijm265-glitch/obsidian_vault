- **P2P 사용 (Master 역할):**
    - **내 PLC가 먼저 말을 거는 주도자**가 됩니다.
    - 상대 장비(인버터, 온도조절기, 타사 PLC 등)의 데이터를 주기적으로 읽어오거나(READ) 명령을 써줄(WRITE) 때 선택합니다.
    - 이 모드를 선택해야 별도의 P2P 통신 설정 창에서 '상대 국번 몇 번의 주소를 몇 초마다 읽어와라' 같은 블록 테이블을 등록할 수 있습니다.
        
- **XGT 서버 (Slave 역할 - LS 전용 프로토콜):**
    - **내 PLC는 가만히 있고, 상대방이 요청할 때만 대답해 주는 상태**입니다.
    - 상대방이 LS 터치패널(XP 시리즈 등)이나 상위 PC 모니터링 프로그램(SCADA 등)일 때 주로 씁니다.
    - 상대방이 "D0번지 값 줘" 하고 LS 전용 프로토콜로 찔러오면, 내 PLC는 래더 작성 없이 자동으로 D0 값을 읽어서 넘겨줍니다.
        
- **모드버스 ASCII / RTU 서버 (Slave 역할 - 범용 표준 프로토콜):**
    - 마찬가지로 **수동적인 대기(Slave) 상태**이지만, 주고받는 언어 규격이 LS 전용 규격이 아니라 전 세계 표준인 Modbus(RTU는 바이너리, ASCII는 텍스트 형태)로 동작합니다.
    - 상대방 장치(타사 HMI, 타사 상위 시스템, 계측기 등)가 Modbus Master일 때 내 PLC의 데이터를 건네주기 위해 선택합니다.

## 모듈 구조

### 인터페이스

상위 제어기와 모듈간 신호를 주고 받는 게이트
#### 입력
- `bCmd_Start` **(Req, Request)**: 상위 제어기가 모듈에게 동작 개시를 요청
- `bCmd_Reset`: 에러 발생시 핸드셰이크 상태를 대기(Reset) 상태로 만들기 위한 신호
#### 출력
- `bOut_Busy`: 모듈이 요청에 의해 작동중임을 알리는 신호 
- `bOut_Done` **(Ack, Acknowledge)**: 모듈이 작업을 완료했음을 알리는 신호

### 핸드셰이크 상태

모듈 내부 로직에 다음과 같은 4단계의 상태 제어 구조가 갖추어져야 함
$$요청\space대기 \rightarrow 동작\space실행 \rightarrow 응답\space출력 \rightarrow 요청\space해제\space대기$$

1. **\[State 0\] 요청 대기 (IDLE, READY)**: `bOut_Done`을 `FALSE`로 유지하면서 상위 제어기가 `bCmd_Start`를 `TRUE`로 전환하는것을 대기
2. **\[State 10\] 실행 (Run)**: `bOut_Busy := TRUE`를 출력하고 모듈의 동작을 실행 (실린더 제어, 컨베이어 제어 등)
3.  **\[State 20\] 완료 응답 (Ack)**: 작업 완료 센서를 감지하면 동작을 종료하고 `bOut_Busy := FALSE`, `bOut_Done := TRUE`를 출력.
4. **\[State 20 내 대기\] 핸드셰이크 해제 감지**: 상위 제어기가 `bOut_Done`을 확인하고 **`bCmd_Start`를 `FALSE`로 끌 때까지 복귀하지 않고 대기**. 상위의 요청이 꺼진 것을 확인한 후에야 `bOut_Done := FALSE`로 바꾸고 \[State 0\]으로 복귀.


### 상태 고정 및 이중 실행 방지 로직

상위 제어기의 스캔 타임이나 제어 주기 차이로 발생할 수 있는 신호 오작동을 막기위해 Robust하게 설계해야 함

- `bOut_Done`과 같은 신호의 Rising이나 Falling을 감지하지 못할 수 있으므로 상위 제어기가 이를 인지하여 `bCmd_Start`를 끌 때 까지 `bOut_Done`의 상태를 유지해야 함 
- `bCmd_Start`가 켜져 있는 동안 작업이 끝나더라도 바로 재시작되지 않도록 `bCmd_Start`가 OFF되는 과정을 거치도록 설계 (State기반 Transition으로 구현)
### 비정상 상황에 대비한 예외 및 타임아웃 처리

작동중 하드웨어 고장이나 신호 단선에 의한 Deadlock을 방지하기 위해 구현

- \[State 10\]에 진입하였으나 제한시간 내 작업이 완료되지 않으면 타임아웃을 발생시켜 `bOut_Error`를 `TRUE`로 만들고 에러코드를 출력해야 함
- 에러 발생시 `bOut_Done`을 `TRUE`로 하지 않고 작동을 즉시 중단하여 상위 제어기가 다음 공정을 진행하지 않도록 해야 함.

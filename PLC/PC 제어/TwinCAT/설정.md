- PLC를 켜고 끄거나 통신 모드를 바꾸는 기능
### Config Mode 
- 시스템을 설정 모드로 전환
- EherCAT 네트워크 스캔, 하드웨어 I/O 점검, 서보 드라이브 튜닝 등

### Activate Configuration
- IDE에서 설정한 하드웨어 트리, I/O 매핑, 태스주기, 라이선스 정보 등을 런타임 엔진에 Write함

### Restart TwinCAT System
- Write한 내용을 적용하기 위해 재시작

## 2. 프로그램 레벨
### Build Solution
- ST/LD의 문법 오류, 변수 선언 누락 , 타입 불일치등을 검사하고 실행가능한 머신 코드로 변환

### Login/Logout
- 컴파일된 코드를 실행중이 TwinCAT 런타임에 다운로드하고, 개발 툴과 런타임간 통신 채널을 열어 실시간 모니터링 세션에 접속

| **구분**             | **LS 환경**                                   | **TwinCAT 환경**                                     |
| ------------------ | ------------------------------------------- | -------------------------------------------------- |
| **개발 소프트웨어 (IDE)** | **XG5000** (화면에 띄워 래더 짜는 창)                 | **TcXaeShell** (지금 보고 계신 Visual Studio 창)          |
| **PLC 본체 기계**      | 책상 위에 놓인 **실제 플라스틱 PLC 기기 (XGB 등)**         | **TwinCAT System** (Windows 안에 가상으로 구축된 하드웨어 틀)    |
| **PLC CPU 엔진**     | PLC 기기 내부의 **CPU 칩** (전원 켜면 RUN 램프 들어오는 상태) | **TwinCAT Runtime** (작업표시줄 우측 하단의 **초록색 신호등 아이콘**) |
| **프로그램/로직**        | XG5000에서 작성한 **스캔 프로그램**                    | POU에 작성한 **MAIN 코드 (ST / LD)**                     |
- **Activate Configuration:**
    LS PLC의 베이스 슬롯에 실제 입력 모듈, 출력 모듈, 통신 카드를 꽂고 딥스위치를 맞춘 뒤 **PLC 메인 전원을 껐다 켜서 하드웨어를 인식시키는 과정**입니다.
    
- **Build Solution:**
    XG5000에서 작성한 래더가 문법적으로 맞는지 PC에서 ‘프로그램 검사’하는 과정입니다. (PLC 기계와는 아직 무관함)
    
- **Login:**
    검사가 끝난 프로그램을 통신 케이블(USB/이더넷)을 통해 **켜져 있는 PLC CPU(런타임)에 다운로드하고 모니터링 모드로 들어가는 과정**입니다.
    
- **Logout:**
    모니터링 화면만 닫고 **통신 케이블을 뽑는 행위**입니다. 케이블을 뽑아도 현장의 PLC 본체(런타임)는 설비를 돌리며 계속 혼자 살아서 돌아갑니다.

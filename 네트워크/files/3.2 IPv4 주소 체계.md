## 1. IPv4 주소 체계
IPv4는 컴퓨터가 이해하는 **32비트(Bit) 이진수**로 구성된 논리적 주소 체계입니다.
### 💡 점4성기법 (Dotted-Decimal Notation)
- **32비트 이진수 표현:** `11000000 10101000 00000000 00000001` (사람이 읽고 외우기 너무 어려움)

- **점4성기법 적용:** 32비트를 8비트(1바이트 = 1옥텟)씩 4개의 덩어리로 쪼개고, 각 덩어리를 십진수로 변환하여 점(`.`)으로 구분합니다.
    $$\text{11000000} . \text{10101000} . \text{00000000} . \text{00000001} \implies \mathbf{192.168.0.1}$$
- **표현 가능 주소 개수:** $2^{32} \approx \mathbf{42억 9,496만 7,296개}$

## 2. 클래스풀 주소 체계 (Classful Addressing)
인터넷 초기, IP 주소를 효율적으로 나누어 주기 위해 **네트워크 크기(규모)에 따라 클래스 A, B, C, D, E 5가지로 구분**했던 정적 할당 방식입니다.


```
[ Class A ] ┌─────────────┬───────────────────────────────────────────┐
            │ Network ID  │               Host ID (24비트)             │
            └─────────────┴───────────────────────────────────────────┘
[ Class B ] ┌───────────────────────────┬───────────────────────────┐
            │       Network ID          │       Host ID (16비트)    │
            └───────────────────────────┴───────────────────────────┘
[ Class C ] ┌───────────────────────────────────────────┬─────────────┐
            │               Network ID                  │ Host ID(8비트)│
            └───────────────────────────────────────────┴─────────────┘
```
### 🏷️ 클래스별 범위 및 특징

- **Class A (대규모 네트워크)**
    - **구조:** 첫 8비트 = Network ID / 나머지 24비트 = Host ID
    - **첫 옥텟 범위:** `0.0.0.0` ~ `127.255.255.255` (첫 비트가 `0`으로 시작)
    - **할당 가능 호스트 수:** 네트워크당 약 **1,677만 개** ($2^{24}-2$)
        
- **Class B (중규모 네트워크)**
    - **구조:** 앞 16비트 = Network ID / 나머지 16비트 = Host ID
    - **첫 옥텟 범위:** `128.0.0.0` ~ `191.255.255.255` (첫 비트가 `10`으로 시작)
    - **할당 가능 호스트 수:** 네트워크당 약 **65,534 개** ($2^{16}-2$)
        
- **Class C (소규모 네트워크)**
    - **구조:** 앞 24비트 = Network ID / 나머지 8비트 = Host ID
    - **첫 옥텟 범위:** `192.0.0.0` ~ `223.255.255.255` (첫 비트가 `110`으로 시작)
    - **할당 가능 호스트 수:** 네트워크당 **254 개** ($2^{8}-2$)
        
- **Class D (멀티캐스트 전용):** `224.0.0.0` ~ `239.255.255.255` (일대다 전송용)
    
- **Class E (연구/실험용):** `240.0.0.0` ~ `255.255.255.255` (보존 영역)
    

> 💡 **호스트 개수 계산 시 $-2$를 빼는 이유:**
> - 호스트 ID가 모두 `0`인 주소 = **네트워크 자체 주소 (Network Address)**
> - 호스트 ID가 모두 `1`인 주소 = **해당 네트워크의 전체 방송 주소 (Broadcast Address)**
>    이 2개는 개별 기기(호스트)에 할당할 수 없기 때문에 제외합니다.
>     

## 3. 클래스풀 주소 체계의 한계

클래스풀 방식은 인터넷이 폭발적으로 성장하면서 결정적인 문제점들에 봉착했습니다.

1. **심각한 IP 주소 낭비**
    - 호스트 500개가 필요한 기업이 있다면 Class C(254개)로는 부족하므로 Class B(65,534개)를 할당받아야 했습니다.
    - 결과적으로 나머지 65,000여 개의 IP 주소가 **사용되지 않고 버려지는 극심한 낭비**가 발생했습니다.
        
2. **IPv4 주소 고갈 가속화**
    - 비효율적인 경계선(8비트 단위) 할당 구조로 인해 42억 개의 IPv4 주소가 순식간에 바닥나기 시작했습니다.
        
### 💡 해결책 (이후 등장하는 기술들)

이 클래스풀의 한계를 극복하기 위해 등장한 개념들이 바로 다음에 배우시게 될 **CIDR(Classless Inter-Domain Routing, 서브넷 마스크를 이용해 자유롭게 쪼개는 방식)**, **사설 IP/NAT(공유기 개념)**, 그리고 IPv6(128비트 확대)입니다!

## 1. L2 스위치(Switch)의 핵심 기능 및 동작 원리

L2 스위치는 OSI 2계층(데이터 링크 계층)에서 동작하며, 이더넷 프레임의 목적지 MAC 주소(Destination MAC)를 읽어 해당 장비가 연결된 포트로 데이터를 정교하게 분기해 주는 핵심 네트워크 장비입니다.

스위치는 내부에 MAC 주소 테이블 (MAC Address Table / CAM Table)이라는 이정표를 가지고 있으며, 이 테이블을 생성하고 유지 관리하기 위해 **5가지 핵심 동작**을 수행합니다.

1. **Learing**: 출발지 MAC 주소를 보고 테이블에 등록
2. **Flooding**: 목적지 MAC을 모르면 전체 포트로 복사 전송
3. **Fowarding**: 목적지 MAC을 알면 해당 포트로만 1:1 전송
4. **Filtering**: 출발지와 목적지가 같은 포트면 차단
5. **Aging**: 일정 시간 통신 없으면 테이블에서 삭제

### ① Learning (학습)
- **동작:** 프레임이 스위치 포트로 들어올 때, 이더넷 헤더의 '출발지 MAC 주소(Source MAC)'를 읽어 \[포트 번호 - MAC 주소\]를 매핑하여 테이블에 기록합니다.
- **특징:** 스위치는 프레임이 들어오는 순간(송신 기기의 주소)에만 학습하며, 목적지 MAC을 통해서는 학습하지 않습니다.
    
### ② Flooding (플러딩 / 넘침)
- **동작:** 프레임의 '목적지 MAC 주소'가 MAC 주소 테이블에 **없을 때(Unknown Unicast)**, 혹은 목적지가 브로드캐스트(`FF:FF:FF:FF:FF:FF`)일 때 발생합니다.
- **특징:** 프레임이 들어온 수신 포트를 제외한 **나머지 모든 활성화된 포트로 프레임을 복사하여 전송**합니다.
    
### ③ Forwarding (포워딩 / 전달)
- **동작:** 프레임의 '목적지 MAC 주소'가 MAC 주소 테이블에 이미 등록되어 있을 때 발생합니다.
- **특징:** 목적지 MAC과 매핑된 특정 포트 하나로만 1:1 정확하게 데이터를 전달(Unicast)합니다. (불필요한 네트워크 대역폭 소모 방지)

### ④ Filtering (필터링 / 차단)
- **동작:** 목적지 MAC 주소가 **프레임이 들어온 포트와 동일한 포트**에 위치할 때 발생합니다.
- **특징:** 스위치는 해당 프레임을 다른 포트로 넘기지 않고 **즉시 버립니다(Drop)**. (동일 세그먼트 내의 불필요한 트래픽이 다른 포트로 퍼지는 것을 막음)

### ⑤ Aging (에이징 / 노화)
- **동작:** MAC 주소 테이블에 등록된 항목마다 타이머(기본 약 300초 / 5분)를 동작시켜, 일정 시간 동안 해당 MAC 주소로부터 **새로운 프레임이 들어오지 않으면 테이블에서 자동 삭제**합니다.
- **목적:** 장비가 탈착되거나 포트 위치가 변경되었을 때, 오래된 잘못된 정보를 지우고 **테이블 메모리 공간을 효율적으로 관리**하기 위함입니다. (해당 MAC에서 다시 프레임이 들어오면 타이머는 리셋됨)
## 2. MAC 주소 테이블 생성 과정 (실제 통신 시나리오)

```
[PC A: AA:AA] (포트 1) ───► [ L2 스위치 ] ───► (포트 2) [PC B: BB:BB]
```

### 시나리오: PC A가 PC B에게 데이터를 처음 보낼 때
1. **PC A ➔ 스위치 프레임 전송**
    - 출발지 MAC: `AA:AA` / 목적지 MAC: `BB:BB`
        
2. **Learning (학습)**
    - 스위치는 포트 1로 들어온 프레임을 보고 `포트 1 = AA:AA`를 MAC 주소 테이블에 기록합니다.
        
3. **Table Lookup & Flooding (조회 및 플러딩)**
    - 목적지 MAC인 `BB:BB`를 테이블에서 조회하지만, 아직 등록되어 있지 않습니다 (Unknown Unicast).
    - 스위치는 포트 1을 제외한 **나머지 모든 포트(포트 2 등)로 프레임을 Flooding**합니다.
        
4. **PC B의 응답 ➔ Learning & Forwarding**
    - PC B가 프레임을 받고 답장(출발지 MAC: `BB:BB` / 목적지 MAC: `AA:AA`)을 보냅니다.
    - 스위치는 포트 2로 들어오는 답장을 보고 `포트 2 = BB:BB`를 테이블에 Learning합니다.
    - 이제 목적지 `AA:AA`는 테이블(포트 1)에 있으므로, 포트 1로만 **Forwarding**합니다.
        
5. **이후 통신**
    - 두 기기의 MAC 주소가 모두 등록되었으므로, 이후 모든 통신은 Flooding 없이 **1:1 Forwarding**으로 빠르게 처리됩니다.

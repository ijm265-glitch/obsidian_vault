## 1. CSMA/CD 메커니즘의 등장 배경

과거 이더넷(Ethernet)은 더미 허브(Dummy Hub)나 하나의 동축 케이블에 여러 컴퓨터가 병렬로 연결된 '공유 매체(Shared Medium) 환경'이었습니다.
모든 장비가 하나의 전선을 공유하다 보니, 두 개 이상의 장비가 동시에 데이터를 발사하면 전기 신호가 겹치며 충돌(Collision)이 발생했습니다. 이 충돌을 최소화하고 매체 점유 질서를 유지하기 위해 고안된 **반두중(Half-Duplex) 매체 접근 제어 프로토콜**이 바로 **CSMA/CD**입니다.

## 2. CSMA/CD의 단계별 작동 원리

CSMA/CD는 통신 매체를 "여러 사람이 하나의 무전기를 공유하여 대화하는 과정"에 비유할 수 있습니다.
```
[1. Carrier Sense] ➔ 전선에 신호가 흐르는지 눈치 보기 (Listen Before Talk)
       │
[2. Multiple Access] ➔ 아무도 안 쓰면 동시에 여러 장비가 데이터 전송 시도
       │
[3. Collision Detection] ➔ 만약 동시에 쏘아 전압이 튀면 충돌 감지!
       │
[4. Jam Signal & Backoff] ➔ 충돌 알림 신호 발사 후 무작위 대기(Exponential Backoff) 후 재시도
```
### 2.1 Carrier Sense (캐리어 감지: 눈치 보기)
- **동작:** 데이터를 송신하려는 노드는 먼저 물리적 매체(전선)에 전기 신호(Carrier)가 흐르고 있는지 감지합니다.
- **상태 판단:**
    - 매체가 사용 중(Busy)이면 신호가 끝날 때까지 대기합니다.
    - 매체가 비어 있음(Idle)을 확인하면 데이터를 전송할 준비를 합니다.
### 2.2 Multiple Access (다중 access: 자유로운 접근)
- **동작:** 매체가 비어있다고 판단되면, 네트워크에 연결된 모든 노드는 **별도의 순서 예약 없이 누구나 자유롭게 데이터 프레임을 발사**할 수 있습니다.
- **문제점:** 매체 상태 판단과 실제 전파 도달 시간 차이(지연 시간, Propagation Delay) 때문에, **두 노드가 동시에 "비어있다"고 판단하여 각자 프레임을 전송할 위험**이 상시 존재합니다.
    

### 2.3 Collision Detection (충돌 감지: 부딪힘 확인)
- **동작:** 데이터를 전송하는 와중에도 노드는 자기가 쏜 신호와 선로의 전압 변화를 계속 모니터링합니다.
- **충돌 발견:** 두 신호가 부딪혀 전압이 이상 수치(Spike)로 튀어 오르면 충돌(Collision)이 터진 것으로 간주합니다.
### 2.4 충돌 후 처리: 잼 신호(Jam Signal) 및 지수 백오프(Exponential Backoff)
1. **잼 신호(Jam Signal) 송출:** 충돌을 감지한 노드는 즉시 **32비트 크기의 잼 신호**를 전체 네트워크로 유포하여, 다른 노드들에게 데이터가 파괴되었음을 알리고 송신을 중단시킵니다.
2. **지수 백오프 (Truncated Binary Exponential Backoff):**
    - 충돌을 일으킨 노드들이 동시에 바로 재전송을 시도하면 또 다시 충돌이 터지므로, **각자 무작위(Random) 대기 시간을 계산하여 기다린 후 재전송**합니다.
    - 충돌이 반복될수록 무작위 난수의 선택 범위($2^k$)를 2배씩 늘려 재충돌 확률을 기하급수적으로 낮춥니다 ($k$: 연속 충돌 횟수).

## 3. 현대 전이중(Full-Duplex) 네트워크에서 CSMA/CD가 불필요해진 이유

현대의 유선 이더넷 환경에서는 **CSMA/CD 알고리즘을 전혀 사용하지 않습니다.
### 3.1 점대점(Point-to-Point) 전용 회로 및 L2 스위치 도입
- 과거의 더미 허브는 모든 포트가 통째로 묶인 공유 매체였으나, 현대 네트워크는 2계층 스위치(Switch)가 모든 장비를 1:1 점대점(Point-to-Point) 링크로 연결합니다.
- 스위치 포트마다 독립된 충돌 도메인(Collision Domain)이 형성되므로 타 장비의 전기 신호와 부딪힐 일 자체가 소멸했습니다.

### 3.2 송신(Tx)과 수신(Rx) 선로의 물리적 분리 (전이중 통신)
- UTP 랜선 내부의 8가닥 선 중 **송신용(Tx) 쌍과 수신용(Rx) 쌍이 물리적으로 완전히 분리**되었습니다.
- **전이중 통신(Full-Duplex):** 내가 데이터를 보내는 길(Tx)과 상대방이 데이터를 보내는 길(Rx)이 다르므로, 동시에 데이터를 주고받아도 물리적인 전기 신호 중첩(충돌)이 일어날 가능성이 0%입니다.

## 1. PDU (Protocol Data Unit)란?

PDU(프로토콜 데이터 단위)는 계층화된 네트워크 모델에서 **각 계층이 다루는 데이터의 묶음 단위**를 의미
상위 계층의 데이터가 하위 계층으로 내려갈 때마다 각 계층의 제어 정보(헤더)가 새로 덧붙거나 쪼개지며, 각 단계마다 부르는 명칭이 달라짐

| **계층 (Layer)**                  | **PDU 명칭**                                            | **주요 헤더 포함 정보**                                      | **핵심 역할 및 특징**                                                                                      |
| ------------------------------- | ----------------------------------------------------- | ---------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| **7~5층. 응용 계층** _(Application)_ | **Data / Message**                                    | 응용 프로토콜 헤더 (HTTP, DNS 등)                             | 사용자가 실제로 주고받는 순수한 데이터 및 메시지 자체입니다.                                                                  |
| **4층. 전송 계층** _(Transport)_     | **Segment** (TCP)<br><br>  <br><br>**Datagram** (UDP) | **출발지/목적지 포트 번호**, Sequence Number, ACK Number       | - **프로세스(방 번호)를 식별**합니다.<br><br>  <br><br>- 데이터가 클 경우 전송 단위에 맞게 조각(지상파 분할)을 냅니다.                    |
| **3층. 인터넷 계층** _(Internet)_     | **Packet**                                            | **출발지/목적지 IP 주소**, TTL, Protocol                     | - **논리적 목적지(IP) 위치**를 지정합니다.<br><br>- 전 세계 라우터 고속도로망을 타고 길 찾기(라우팅)를 수행합니다.                          |
| **2층. 데이터 링크** _(Data Link)_    | **Frame**                                             | **출발지/목적지 MAC 주소**, EtherType, **FCS (트레일러: 오류 검출)** | - **물리적 인접 장비(MAC 주소)** 간 데이터 이동을 담당합니다.<br><br>- 전송 중 신호에 에러가 생겼는지 검출하기 위해 뒤에 **트레일러(FCS)**를 붙입니다. |
| **1층. 물리 계층** _(Physical)_      | **Bits**                                              | 없음                                                   | 데이터 프레임을 랜선, 광케이블, 무선 주파수 등을 타고 흐르는 **`0`과 `1`의 전압/빛 신호**로 변환한 상태입니다.                               |
## 송신 - 라우터 - 수신 과정에서 라우터가 하는 일

- **1계층: \[물리 계층\] 신호 변환 및 물리적 수신 (Signal Demodulation & Bit Restoration)**
    - 수신 인터페이스(PHY)를 통해 인입된 전압/광 신호(Physical Signal)를 디지털 비트 스트림(Bitstream)으로 복원합니다.
        
- **\[2계층: 데이터 링크 계층\] 프레임 검증 및 역캡슐화 (Frame Validation & Decapsulation)**
    - **물리 주소 식별:** 이더넷 프레임 헤더의 수신지 MAC 주소(Destination MAC Address)를 확인하여, 해당 라우터의 수신 인터페이스 MAC 주소와 일치하는지 검증합니다.
    - **무결성 검사 및 역캡슐화:** 프레임 트레일러의 FCS(Frame Check Sequence)를 통해 순환 중복 검사(CRC)를 수행한 뒤, 이상이 없으면 L2 헤더 및 트레일러를 해제(Decapsulation)하고 상위 L3 페이로드(Payload)를 추출합니다.
        
- **\[3계층: 네트워크 계층\] 경로 결정 및 라우팅 (Routing Lookup & Forwarding Decision)**
    - **수신지 논리 주소 조회:** L3 IP 패킷 헤더의 최종 수신지 IP 주소(Destination IP Address)를 추출합니다.
    - **경로 결정 (Routing Lookup):** 라우팅 테이블(Routing Table) 및 FIB(Forwarding Information Base)를 참조하여, 최적의 **차기 노드(Next-hop)** 및 송출 인터페이스(Egress Interface)를 결정합니다. _(이 과정에서 TTL(Time To Live) 값을 1 감쇄하고 Header Checksum을 재계산합니다.)_
        
- **\[2계층: 데이터 링크 계층\] 프레임 재캡슐화 (Frame Re-encapsulation)**
    - **새로운 L2 프레임 생성:** L3 IP 패킷을 고정한 상태에서, 결정된 송출 인터페이스에 맞게 **L2 헤더를 새롭게 재구성**합니다.
    - **송신지 MAC 주소:** 해당 라우터 송출 인터페이스의 MAC 주소 (Source MAC)
    - **수신지 MAC 주소:** ARP 테이블 조회를 통해 획득한 차기 노드(Next-hop 장비 또는 최종 목적지 Host)의 MAC 주소 (Destination MAC)
        
- **\[1계층: 물리 계층\] 신호 변환 및 물리적 송출 (Signal Modulation & Transmission)**
    - 재캡슐화된 데이터 프레임을 송출 인터페이스의 매체(UTP, Optical 등) 특성에 맞게 **물리 신호(Electrical/Optical Signal)로 변조하여 전송**합니다.

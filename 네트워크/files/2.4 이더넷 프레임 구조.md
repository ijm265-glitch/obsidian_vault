## 1. 이더넷 프레임 (Ethernet Frame)의 정의

- **정의:** OSI 2계층(데이터 링크 계층)에서 상위 계층(3계층 IP 패킷 등)의 데이터를 물리적 매체(랜선, 광케이블)로 전송하기 위해 제어 정보(헤더 및 트레일러)를 덧붙여 포장한 기본 전송 단위(PDU)입니다.
- **표준 규격:** 현재 전 세계 유선 네트워크는 **Ethernet II (DIX 2.0)** 표준 프레임 형식을 압도적으로 사용하고 있습니다.


| 구분        | Header (14 + 8 Bytes) | Header (14 + 8 Bytes) | Header (14 + 8 Bytes) | Header (14 + 8 Bytes) |  Header (14 + 8 Bytes)  |       Payload       | Trailer (4 Bytes) |
| :-------- | :-------------------: | :-------------------: | :-------------------: | :-------------------: | :---------------------: | :-----------------: | :---------------: |
| **필드명**   |     **Preamble**      |        **SFD**        |  **Destination MAC**  |    **Source MAC**     |      **EtherType**      | **Payload (Data)**  |   **FCS (CRC)**   |
| **크기**    |        7 Bytes        |        1 Byte         |        6 Bytes        |        6 Bytes        |         2 Bytes         |   46 ~ 1500 Bytes   |      4 Bytes      |
| **주요 역할** |       비트 동기화 신호       |   프레임 시작 표시 (`11`)    |      수신지 MAC 주소       |      출발지 MAC 주소       | 상위 프로토콜 지정 (`0x0800` 등) | 상위 계층 데이터 (IP 패킷 등) |  오류 검출 (CRC-32)   |
## 2. 세부 필드 역할 및 기능

### 2.1 헤더 (Header): 데이터 전달을 위한 제어 정보

1. **Preamble (서문 / 동기화 신호) - 7 Bytes**
    - **역할:** 비트 동기화(Bit Synchronization).
    - **구조:** `10101010` 비트 패턴이 7바이트 동안 연속으로 흘러나옵니다. 수신 측 랜카드가 클록(Clock) 신호를 맞추어 **"곧 신호가 들어오니 준비해라!"** 하고 대비하게 만듭니다.
        
2. **SFD (Start Frame Delimiter / 프레임 시작 구문) - 1 Byte**
    - **역할:** 프레임의 실제 시작점을 알림.
    - **구조:** `10101011` 비트 패턴 (마지막이 `11`로 끝남). 수신 랜카드가 이 `11`을 감지하는 순간 **"다음 비트부터가 진짜 목적지 MAC 주소다!"** 하고 프레임 해석을 시작합니다.
        
3. **목적지 MAC 주소 (Destination MAC Address) - 6 Bytes (48 Bits)**
    - **역할:** 프레임을 수신할 **최종 인접 노드(장비)의 물리 주소**.
    - 수신 기기는 이 주소가 자신의 MAC 주소이거나 그룹/전체 주소(`b0=1`)인 경우에만 프레임을 받아들입니다.
        
4. **출발지 MAC 주소 (Source MAC Address) - 6 Bytes (48 Bits)**
    - **역할:** 프레임을 송신한 **출발지 노드의 물리 주소**.
    - 스위치는 이 주소를 보고 해당 포트에 어느 장비가 꽂혀있는지 학습(MAC Address Learning)합니다.

5. **EtherType (이더타입 / 상위 프로토콜 식별자) - 2 Bytes**
    - **역할:** 프레임의 데이터 영역(Payload)에 실려 있는 **3계층 상위 프로토콜의 종류**를 지정합니다.
    - **대표적인 EtherType 값 (16진수):**
        - `0x0800`: **IPv4** 패킷
        - `0x0806`: **ARP** (주소 결정 프로토콜)
        - `0x86DD`: **IPv6** 패킷
     - 이더넷 프레임을 받아서 헤더랑 트레일러의 정보를 해체하고 페이로드를 3계층 해석으로 보내기 위해서 2계층에 이더타입을 적는다라는거지?
            

### 2.2 데이터 영역 (Payload)

- **Payload (데이터 / IP 패킷) - 46 ~ 1500 Bytes**
    - **역할:** 3계층에서 내려온 실제 IP 패킷이나 데이터가 들어가는 공간입니다.
    - **MTU (Maximum Transmission Unit):** 이더넷에서 전송 가능한 최대 데이터 크기는 기본 **1500바이트**로 제한됩니다.
    - **패딩 (Padding):** 상위 데이터가 너무 작아 최소 프레임 크기인 64바이트(헤더+트레일러 18바이트 제외 시 최소 데이터 46바이트)를 채우지 못할 경우, 뒤에 의미 없는 `0` 비트를 강제로 채워 46바이트를 맞춥니다. _(이유: 과거 CSMA/CD 환경에서 최소 충돌 감지 시간을 확보하기 위함)_
        
### 2.3 트레일러 (Trailer): 오류 검출 정보
- **FCS (Frame Check Sequence / 오류 검출용 필드) - 4 Bytes**
    - **역할:** 데이터 전송 도중 노이즈나 신호 찌그러짐으로 인해 비트가 훼손되었는지 검증(Error Detection)합니다.
    - **원리 (CRC-32 알고리즘):**
        1. 송신 측 랜카드가 목적지 MAC부터 Payload까지의 전체 데이터를 **CRC(순환 중복 검사) 수학 공식**으로 계산하여 4바이트 값을 구해 FCS에 넣습니다.
        2. 수신 측 랜카드도 프레임을 받은 후 똑같은 CRC 계산을 수행합니다.
        3. **송신 FCS 값 == 수신 계산값:** 에러 없음 (정상 수신 후 상위 계층으로 전달)
        4. **송신 FCS 값 $\ne$ 수신 계산값:** **데이터 파손!** (미련 없이 해당 프레임을 즉시 폐기/Drop 합니다. _2계층은 재전송을 요청하지 않고 버리기만 합니다._)


### 1. 라우팅 테이블(Routing Table)의 핵심 구성 요소

라우팅 테이블은 라우터가 가지고 있는 '네트워크 지도(내비게이션 지도)'입니다. 패킷이 들어오면 라우터는 목적지 IP와 이 테이블을 대조하여 어디로 내보낼지 결정합니다.

|**주요 구성 요소**|**의미 및 역할**|**비유**|
|---|---|---|
|**Destination (목적지 대역)**|패킷이 최종적으로 가고자 하는 **목적지 네트워크 주소** (예: `10.0.0.0/8`, `0.0.0.0/0`)|도착 도시 / 동네|
|**Subnet Mask / Prefix**|목적지 네트워크의 크기 및 대역 범위를 나타내는 마스크|상세 주소 구분선|
|**Next Hop (Gateway)**|목적지로 가기 위해 **다음에 거쳐야 할 경유지 라우터 IP**|다음 고속도로 IC / 톨게이트|
|**Interface (출력 포트)**|패킷을 밖으로 보낼 **내 라우터의 물리적/논리적 랜포트** (예: `eth0`, `wlan0`)|내가 나가는 도로 출구 (1번 게이트 등)|
|**Metric (거리/비용)**|목적지까지 가는 데 드는 **거리 또는 비용 점수** (낮을수록 우수한 경로)|예상 소요 시간 / 통행료|

> 💡 **Longest Prefix Match (가장 긴 일치 원칙):**
> 
> 라우터는 라우팅 테이블을 조회할 때 목적지 IP와 **서브넷 마스크가 가장 길게(상세하게) 일치하는 경로를 최우선**으로 선택합니다. (어디에도 해당하지 않으면 `0.0.0.0/0`인 기본 게이트웨이로 던집니다.)

### 2. 정적 라우팅 (Static Routing) vs 동적 라우팅 (Dynamic Routing)

라우터가 라우팅 테이블을 작성하는 방식은 사람이 직접 적어주는가, 장비들끼리 서로 대화하며 만드는가에 따라 나뉩니다.

```
               ┌── 정적 라우팅 (Static): 사람이 직접 관리자가 수동 입력
  라우팅 방식 ──┤
               └── 동적 라우팅 (Dynamic): 라우터끼리 프로토콜로 정보 교환
```

|**구분**|**정적 라우팅 (Static Routing)**|**동적 라우팅 (Dynamic Routing)**|
|---|---|---|
|**작성 주체**|**네트워크 관리자(사람)**가 수동으로 입력|라우터 간 **라우팅 프로토콜**이 자동으로 생성|
|**연산/자원**|라우터 CPU/메모리 연산 부담 **없음**|라우터 연산 자원 및 대역폭 **소모**|
|**장점**|구조가 단순함, 라우터 부하 적음, **보안성 높음**|네트워크 변화(선로 장애 등) 발생 시 **자동으로 우회 경로 생성**|
|**단점**|경로 장애 시 우회 불가, **규모가 커지면 관리 불가능**|설비 비용 증가, 프로토콜 설정이 복잡함|
|**주요 사용처**|소규모 네트워크, **기본 게이트웨이 설정**|기업체 망, 데이터센터, 통신사 백본망|

### 3. 주요 라우팅 프로토콜 종류 (RIP, OSPF, BGP)

동적 라우팅을 수행할 때 어느 범위(내부망 vs 인터넷 전체)에서 통신하느냐에 따라 IGP(내부)와 EGP(외부)로 나뉩니다.

```
                        ┌── Distance Vector ── RIP (거리/Hop 수 기준)
          ┌── IGP (내부) ┤
라우팅 프로토콜 ┤          └── Link State ────── OSPF (속도/대역폭 기준, 가장 많이 씀)
          │
          └── EGP (외부) ────────────────────── BGP (AS 간 통신, 인터넷 전체의 내비)
```

#### ① RIP (Routing Information Protocol)
- **분류:** IGP (내부 라우팅 프로토콜) / Distance Vector 방식
- **특징:** 목적지까지 거쳐가는 라우터 개수(Hop Count)만으로 최적 경로를 산출합니다.
- **한계:** 최대 Hop 수가 **15개로 제한**되어 있고, 선로의 속도(대역폭)를 고려하지 않아서 요즘 대규모 망에서는 거의 사용되지 않는 고전 프로토콜입니다.
    

#### ② OSPF (Open Shortest Path First)
- **분류:** IGP (내부 라우팅 프로토콜) / Link State 방식
- **특징:** 기업체 내부망에서 가장 널리 쓰입니다. 단순 거리뿐만 아니라 회선 속도(대역폭/지연시간)를 계산하여 가장 빠른 경로(Dijkstra 알고리즘)를 찾습니다.
- **장점:** 네트워크 변화 시 수초 내로 신속하게 수렴(Convergence)하여 우회 경로를 만듭니다.
    

#### ③ BGP (Border Gateway Protocol)
- **분류:** EGP (외부 라우팅 프로토콜) / Path Vector 방식
- **특징:** **인터넷 전체를 움직이는 거대한 라우팅 프로토콜**입니다. KT, SKT, LGU+, AT&T, 구글 등 각 통신사/기업의 독자적인 네트워크 단위(AS, Autonomous System)들끼리 서로 경로 정보를 주고받을 때 사용합니다.
- **역할:** 우리가 아까 `traceroute`를 했을 때 한국 통신사 망에서 일본 NTT 망(`gin.ntt.net`)으로 넘어가고 Cloudflare로 넘어갈 수 있었던 이유가 바로 이 BGP가 거대한 국가/통신사 간 길을 열어주었기 때문입니다.

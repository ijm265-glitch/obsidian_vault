## 1. ARP(Address Resolution Protocol)의 정의

- **정의:** OSI 3계층의 논리적 주소(IP 주소)를 기반으로, 같은 LAN(동일 서브넷) 내에서 통신하기 위해 필수적인 2계층 물리적 주소(MAC 주소)를 동적으로 알아내는 프로토콜입니다.
    
- **필요성:** 상위 애플리케이션이나 IP 계층은 상대방의 IP 주소만 알고 있습니다. 하지만 이더넷 프레임을 만들어 전선/광케이블로 쏘려면 '목적지 MAC 주소'를 헤더에 반드시 적어야 하므로, 이를 연결(Mapping)해 주는 ARP가 필수적입니다.

## 2. ARP의 기본 동작 과정

ARP는 크게 질문(Request)과 응답(Reply)의 2단계로 동작합니다.
### ① ARP Request (요청) - 브로드캐스트 (1:N)
- **상황:** PC A가 `192.168.0.3` (PC B)에게 데이터를 보내고 싶은데, PC B의 MAC 주소를 모를 때 발생합니다.
- **전송 방식:** **브로드캐스트(Broadcast)**
    - **목적지 MAC:** `FF:FF:FF:FF:FF:FF` (스위치가 접속된 모든 포트로 Flooding)
    - **내용:** _"IP가 `192.168.0.3`인 장비 누구니? 네 MAC 주소 좀 내 MAC(`AA:AA`)으로 알려줘!"_

### ② ARP Reply (응답) - 유니캐스트 (1:1)
- **상황:** 네트워크 전체로 퍼진 요청 프레임을 수신한 모든 기기 중, **해당 IP(`192.168.0.3`)를 소유한 PC B만** 반응합니다. _(다른 기기들은 자신의 IP가 아니므로 패킷을 Drop합니다.)_
- **전송 방식:** **유니캐스트(Unicast)**
    - PC B는 이미 Request 헤더를 통해 PC A의 MAC 주소를 알게 되었으므로, PC A에게만 1:1로 직접 응답합니다.
    - **내용:** _"내가 `192.168.0.3`이야! 내 MAC 주소는 `BB:BB`란다."_

## 3. ARP Cache Table (ARP 캐시 테이블)

- **정의:** 매번 데이터를 보낼 때마다 ARP Request를 날리면 네트워크 대역폭 손실과 지연(Latency)이 발생하므로, 한 번 알아낸 [IP 주소 - MAC 주소] 매핑 정보를 메모리에 임시 저장해 두는 테이블입니다.
- **확인 방법 (CLI):** `arp -a` 명령어로 현재 내 PC에 저장된 ARP 캐시 목록을 조회할 수 있습니다.
- **유지 시간 (Aging):**
    - 매핑 항목은 영구적이지 않으며, 보통 **수분~십수 분(예: Windows 기준 기본 2분~10분)** 동안 통신이 없으면 자동 삭제됩니다.
    - 기기의 랜카드가 교체되거나 IP가 바뀌었을 때 잘못된 정보가 계속 유지되는 것을 방지합니다.
    
GARP(Gratuitous ARP, 무상 ARP)는 한 마디로 "아무도 안 물어봤는데, 스스로 손들고 자기 정보(IP & MAC)를 네트워크 전체에 방송하는 특수 ARP"입니다.
일반 ARP가 _"이 IP 가진 사람 MAC 주소 좀 말해줘!"_ 하고 묻는 **‘질문과 응답’** 방식이라면, GARP는 ‘단방향 공지사항’입니다.

## 1. GARP 
다른 기기들이 ARP 캐시 테이블을 변경하기 위해 사용
GARP가 일반 ARP와 다른 결정적 차이는 **‘Sender(보내는 이)’와 ‘Target(목적지)’의 IP 주소가 똑같다**는 점입니다.

- **출발지 IP:** `내 IP 주소`
- **목적지 IP:** `내 IP 주소` (자기 자신을 지정!)    
- **목적지 MAC:** `FF:FF:FF:FF:FF:FF` (네트워크 전체에 쏘는 브로드캐스트)
```
[ 1. L2 (Ethernet Header) ]
  - 목적지 MAC: FF:FF:FF:FF:FF:FF (브로드캐스트)
  - 출발지 MAC: NEW-MAC (새로 바뀐 MAC 주소)
  ➔ "브로드캐스트네? 일단 내 랜카드가 받아서 패킷을 열어보자!"

        │
        ▼

[ 2. L3 (ARP Body) ]
  - Sender IP : 192.168.0.2 (보낸 사람 IP)
  - Sender MAC: NEW-MAC     (보낸 사람 MAC)
  ➔ "L3/ARP 바디 안의 [Sender IP]와 [Sender MAC]을 확인하자!"

        │
        ▼

[ 3. ARP Cache Table 검사 & 갱신 ]
  - OS 판단: "어? 내 장부에 192.168.0.2가 등록되어 있네?"
  - 동작: "192.168.0.2의 MAC 주소를 NEW-MAC으로 덮어써서 갱신(Update)해야겠다!"
```

### ① IP 주소 충돌 감지 (Conflict Detection)
- **상황:** PC나 ESP32 같은 장비가 켜지거나 네트워크에 연결될 때, IP를 사용하기 직전 GARP를 쏩니다.
- **원리:** _"나 `192.168.0.2`로 시작할 건데 온 동네 사람 다 들으세요!"_ 하고 쐈을 때, 만약 누군가가 이미 그 IP를 쓰고 있다면 **"어? 그거 내 IP인데?"** 하고 응답(Reply)을 보냅니다.
### ② 주변 기기들의 ARP 캐시 테이블 갱신 (Update)

- **상황:** 내 컴퓨터의 랜카드가 고장 나서 교체했거나, 가상머신(VM)이 다른 서버로 이동하여 MAC 주소가 변경되었을 때 발생합니다.
- **원리:** IP는 그대로인데 MAC 주소만 바뀌면, 주변 PC들과 스위치는 옛날 MAC 주소를 기억하고 있어 데이터가 엉뚱한 곳으로 날아갑니다.
- **결과:** 기기가 바뀌자마자 GARP를 한번 쫙 뿌려주면, 이를 받은 네트워크 안의 모든 컴퓨터와 스위치가 **자기네 장부(ARP 테이블)의 MAC 주소를 최신 정보로 즉시 업데이트**합니다.

### ③ 서버/라우터 이중화 및 고가용성 (HA / VRRP) ★★★
- **상황:** 인터넷 쇼핑몰이나 은행 시스템처럼 절대 죽으면 안 되는 서버는 메인(Active)과 서브(Standby) 2대를 둡니다. 두 서버는 하나의 대표 IP(Virtual IP)를 공유합니다.
- **원리:** 메인 서버가 갑자기 고장 나면, 서브 서버가 0.1초 만에 대표 IP를 승계받습니다.
- **결과:** 서브 서버는 승계받자마자 **전체 네트워크에 GARP를 쏩니다.**
    > _"이제부터 이 대표 IP의 MAC 주소는 나(서브 서버)다!"_
    
- 이 GARP 덕분에 스위치와 이용자들의 트래픽이 즉시 서브 서버로 재배송되어 **서비스가 단 1초도 끊기지 않고 유지**됩니다.
### 💡 딱 한 가지 상황별 디테일 (같은 동네 vs 다른 동네)
이때 OS가 ARP로 알아내는 '목적지 MAC 주소'가 누구의 MAC 주소인가에 따라 두 가지로 나뉩니다.
1. **상대방이 같은 LAN(같은 서브넷)에 있는 경우:**
    - OS는 '상대방 IP'로 ARP를 날려 '상대방 PC의 MAC 주소'를 직접 알아내어 이더넷 프레임에 적습니다.
    
2. **상대방이 외부 인터넷(다른 네트워크)에 있는 경우:**
    - OS는 상대방 PC에 직접 닿을 수 없음을 알고, 인터넷 출구인 '기본 게이트웨이(공유기/라우터)의 IP'로 ARP를 날려 '공유기/라우터의 MAC 주소'를 알아낸 뒤 목적지 MAC에 적습니다. _(최종 목적지 IP는 그대로 유지됩니다.)_

무선 LAN(IEEE 802.11)의 매체 접근 제어 기술인 **CSMA/CA 프로토콜**과 **RTS/CTS 메커니즘**에 대한 정리입니다.

## 1. 무선에서 CSMA/CD가 불가능하고 CSMA/CA를 쓰는 이유

유선 랜(Ethernet)은 CSMA/CD (Carrier Sense Multiple Access with Collision Detection)를 사용하여 충돌을 감지하지만, 무선 랜(Wi-Fi)은 충돌을 사전에 피하는 CSMA/CA (Carrier Sense Multiple Access with Collision Avoidance)를 사용합니다.

### 1) 왜 무선에서는 충돌 감지(Collision Detection)가 물리적으로 불가능할까?

#### ① 신호 감쇄(Attenuation)와 자체 신호 차폐 문제

유선은 닫힌 구리선 내부로 신호가 지나가므로 신호 감쇄가 적고 외부 노이즈가 적습니다.

반면 무선은 공기 중으로 전파가 퍼져나가며 급격하게 감쇄됩니다.

- 송신 안테나가 전파를 출력할 때 **자신의 송신 신호 세기가 수신되는 타인의 신호 세기보다 수만~수십만 배 이상 압도적으로 강합니다.**
    
- 이 때문에 내가 데이터를 쏘고 있는 동안에는 다른 장비가 동시에 쏘아 발생한 미세한 충돌 신호를 **자신의 강한 신호에 묻혀 감지(Detection)할 수 없습니다.**
    

#### ② 숨겨진 노드 문제 (Hidden Node Problem)

```
[ Node A ] ────────► [ Access Point (AP) ] ◄──────── [ Node B ]
 (A는 B의 신호를 못 들음)                       (B는 A의 신호를 못 들음)
```

- Node A와 Node B는 서로의 무선 전파 도달 범위를 벗어나 있습니다.
    
- A와 B가 동시에 AP를 향해 패킷을 쏘면, A와 B는 서로 충돌이 났는지 알 수 없지만 **중간에 위치한 AP에서는 패킷 충돌이 발생**합니다. (충돌 감지 불가능)
    
### 2. CSMA/CA의 동작 원리 (무선 환경의 눈치싸움)

충돌을 감지할 수 없으므로 무선 기기들은 데이터를 보내기 전에 "충돌을 최대한 회피(Avoidance)"하는 전략을 취합니다.

```
1. 매체 감지 (Carrier Sensing)
   └─ 채널이 비어있는가? (IFS 시간 동안 대기)
2. 랜시 백오프 (Random Backoff)
   └─ 비어있다면, 각 기기가 랜덤한 대기 시간(Slot Time) 설정 후 카운트다운
3. 데이터 전송 (Data Transmission)
   └─ 카운트다운이 0이 된 기기가 데이터 전송
4. 수신 확인 (ACK)
   └─ 수신측이 ACK를 돌려주면 성공, 안 오면 충돌로 간주하고 백오프 재시도
```

1. **Carrier Sensing (매체 감지):**
    
    - **물리적 감지:** 안테나로 전파 세기(RSSI)를 측정하여 누군가 채널을 쓰는지 확인합니다.
        
    - **가상 감지 (NAV):** 다른 패킷 헤더에 적힌 **NAV(Network Allocation Vector, 채널 점유 예정 시간)** 정보를 읽어 해당 시간 동안 전송을 대기합니다.
        
2. **IFS (Inter-Frame Space) 대기:**
    
    - 채널이 비어있음을 확인해도 즉시 쏘지 않고, 프레임 간 격격 시간인 **DIFS** 동안 더 대기합니다.
        
3. **Random Backoff (랜덤 대기 시간):**
    
    - DIFS 후에도 경쟁 기기들이 동시 전송하는 것을 막기 위해 $0 \sim CW(\text{Contention Window})$ 범위 내에서 랜덤 정수(Slot Count)를 뽑아 카운트다운합니다.
        
    - 카운트다운이 가장 먼저 $0$이 된 기기가 채널을 차지하고 데이터를 송신합니다.
        

## 2. ACK 프레임과 RTS/CTS 메커니즘

### 1) ACK (Acknowledgement) 프레임: 무선에서의 필수 응답

유선(CSMA/CD)은 충돌이 감지되지 않으면 전송 성공으로 간주합니다. 하지만 무선은 충돌 감지가 안 되므로 **데이터가 무사히 도착했는지 수신자(AP)가 직접 알려줘야만 합니다.**

- 수신 측은 데이터를 올바르게 받으면 **SIFS(가장 짧은 대기시간)** 후 **ACK 프레임**을 송신 측으로 보냅니다.
    
- 송신 측이 데이터 송신 후 일정 시간 내에 ACK를 받지 못하면, **"아, 충돌이 났거나 깨졌구나"** 하고 판단하여 Contention Window($CW$)를 2배로 늘린 뒤 재전송(Backoff)을 시도합니다.
    

### 2) RTS / CTS 메커니즘: 숨겨진 노드 문제의 완벽한 해결책

데이터 크기가 클 때 충돌이 발생하면 채널 낭비가 극심해집니다. 이를 막기 위해 데이터 송신 전에 "길을 먼저 터놓는 신호"를 주고받는 옵션 기능입니다.
```
[ Sender (Node A) ]                  [ Receiver (AP) ]                  [ Hidden Node (Node B) ]
        │                                    │                                    │
        ├────────── 1. RTS (Request) ───────►│                                    │
        │                                    ├────────── 2. CTS (Clear) ─────────►│
        │                                    │   (B는 CTS를 듣고 NAV 설정 후 대기)  │
        │◄───────── 2. CTS (Clear) ──────────┤                                    │
        │                                    │                                    │
        ├────────── 3. DATA Transmission ───►│                                    │
        │                                    │                                    │
        │◄───────── 4. ACK ──────────────────┤                                    │
```

1. **RTS (Request to Send):**
    
    - 송신 노드(A)가 AP에 **"나 이제 데이터 보낼 건데 채널 좀 비워줄래?"** 하는 아주 작은 RTS 프레임을 보냅니다.
        
2. **CTS (Clear to Send):**
    
    - AP는 주변 모든 노드가 들을 수 있도록 브로드캐스트로 **"오케이, A 노드 전송 시작해!"** 하는 CTS 프레임을 쏩니다.
        
3. **숨겨진 노드(B)의 대기:**
    
    - Node B는 Node A의 RTS는 못 들었지만, **AP가 쏜 CTS 프레임은 수신**합니다.
        
    - Node B는 CTS 헤더에 적힌 전송 예정 시간을 읽고, 자신의 NAV(가상 대기 타이머)를 설정하여 전송을 멈추고 대기합니다.
        
4. **안전한 DATA 전송:**
    
    - 충돌 위험이 사라진 상태에서 Node A는 마음 놓고 큰 용량의 DATA를 전송하고, AP로부터 ACK를 받으며 마칩니다.
        

### 요약

- **CSMA/CA:** 무선은 **신호 감쇄 및 자체 전파 간섭** 때문에 충돌 감지(CD)가 불가능하여, **Random Backoff와 Carrier Sensing**을 통해 충돌을 사전 회피(CA)합니다.
    
- **ACK:** 수신 성공 여부를 알 수 없는 무선 특성상 **성공적인 수신을 보증**하기 위해 필수적으로 사용합니다.
    
- **RTS/CTS:** 데이터 전송 전 소형 제어 프레임을 먼저 주고받아 **'숨겨진 노드 문제'로 인한 패킷 충돌을 근본적으로 방지**합니다.

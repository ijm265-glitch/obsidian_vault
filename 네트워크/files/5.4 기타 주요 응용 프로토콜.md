## 1. DHCP (Dynamic Host Configuration Protocol)

클라이언트(PC, 스마트폰 등)가 네트워크에 접속할 때 **IP 주소, 서브넷 마스크, 기본 게이트웨이, DNS 서버 주소** 등의 네트워크 설정을 **자동으로 할당**해 주는 응용 계층 프로토콜입니다. (UDP Port 67/68 사용)

### DORA 과정 (DHCP 4단계 동작 원리)

클라이언트가 IP가 없는 상태에서 방송(Broadcast)을 통해 IP를 받아오는 과정입니다.


```
Client                                  DHCP Server
  │                                          │
  ├────── 1. Discover (Broadcast) ──────────►│  "IP 가지고 있는 서버 누구 있나요?"
  │                                          │
  │◄───── 2. Offer (Unicast/Broadcast) ──────┤  "192.168.0.10 IP 쓸래?"
  │                                          │
  ├────── 3. Request (Broadcast) ───────────►│  "네, 그 IP로 사용할게요!"
  │                                          │
  │◄───── 4. ACK (Unicast/Broadcast) ────────┤  "확정! 승인했습니다."
```

1. **Discover (탐색):** 클라이언트가 네트워크 전체에 단대단 방송(Broadcast: `255.255.255.255`)을 뿌려 DHCP 서버를 찾습니다.
    
2. **Offer (제안):** DHCP 서버가 남아있는 IP 주소 후보 하나를 선택하여 클라이언트에게 제안합니다.
    
3. **Request (요청):** 클라이언트가 제안받은 IP를 사용하겠다고 방송을 통해 요청합니다. (다른 DHCP 서버들에게도 "이 IP 쓰기로 했음"을 알림)
    
4. **ACK (승인):** DHCP 서버가 임대 시간(Lease Time) 및 네트워크 옵션 정보와 함께 사용을 최종 확정해 반환합니다.
    

## 2. ICMP (Internet Control Message Protocol)

네트워크 계층(L3, IP)의 **오류 보고 및 네트워크 상태 진단**을 위해 사용되는 제어 프로토콜입니다. IP 헤더 뒤에 캡슐화되어 전달되지만 L3 계층에서 동작합니다.

### 1) Ping (Packet Internet Groper)

- **목적:** 특정 IP 장비와의 네트워크 연결성(Reachability) 및 왕복 시간(RTT)을 측정합니다.
    
- **원리:**
    
    1. 출발지가 목적지로 **ICMP Echo Request (Type 8)** 메시지를 보냅니다.
        
    2. 목적지가 살아있다면 출발지로 **ICMP Echo Reply (Type 0)** 메시지를 응답합니다.
        

### 2) Traceroute (Tracert)

- **목적:** 목적지 IP까지 가는데 거치는 **모든 라우터(경로)의 IP**를 추적합니다.
    
- **원리 (IP Header의 TTL 이용):**
    
    1. IP 헤더의 **TTL(Time To Live)** 값을 $1$로 설정한 패킷을 전송합니다.
        
    2. 첫 번째 라우터가 TTL을 $1$ 감쇠시켜 $0$이 되면, 패킷을 파기하고 **ICMP Time Exceeded (Type 11)** 메시지를 출발지로 보냅니다. (첫 번째 라우터 IP 확보)
        
    3. TTL을 $2, 3, 4\dots$로 $1$씩 늘려가며 목적지에 도달할 때까지 위 과정을 반복하여 경로상의 라우터 IP들을 순차적으로 알아냅니다.
        

## 3. 원격 접속 프로토콜: TELNET vs SSH

원격으로 서버에 접속하여 명령어를 실행할 때 사용하는 프로토콜입니다.

|**구분**|**TELNET (Telecommunication Network)**|**SSH (Secure Shell)**|
|---|---|---|
|**포트 번호**|TCP **23**|TCP **22**|
|**보안성**|**없음 (평문 전송)**|**강함 (암호화 전송)**|
|**특징**|아이디, 비밀번호, 명령어가 모두 평문(Plaintext)으로 전송되어 스니핑에 매우 취약함|**비대칭키/대칭키 하이브리드 암호화**를 사용하여 세션을 보호함 (현재 표준)|

## 4. 파일 및 메일 전송 프로토콜: FTP / SMTP

### 1) FTP (File Transfer Protocol)

- **목적:** 서버와 클라이언트 간에 **파일을 송수신**하기 위한 프로토콜입니다.
    
- **특징 (2개의 포트 분리 사용):**
    
    - **제어 포트 (TCP 21):** 접속 인증, 명령어 및 제어 신호 전달용 채널
        
    - **데이터 포트 (TCP 20):** 실제 파일 데이터가 전송되는 채널
        
- 보안이 취약한 일반 FTP 대신 SSH 기반의 **SFTP (TCP 22)** 또는 SSL/TLS 기반의 **FTPS**를 주로 사용합니다.
    

### 2) SMTP (Simple Mail Transfer Protocol)

- **목적:** 이메일을 **보내거나(발신), 메일 서버 간에 이메일을 전송**할 때 사용하는 프로토콜입니다. (TCP Port 25, 암호화 시 587/465)
    
- **메일 수신 프로토콜과의 구분:**
    
    - **SMTP:** 클라이언트 $\rightarrow$ 보내는 메일 서버 / 메일 서버 $\rightarrow$ 받는 메일 서버 (**발신/전송 전용**)
        
    - **POP3 / IMAP:** 받는 메일 서버 $\rightarrow$ 클라이언트 (**수신 전용**)
        
        - **POP3 (TCP 110):** 서버에서 메일을 로컬 PC로 다운로드 후 서버 메일 삭제 (기본값)
            
        - **IMAP (TCP 143):** 서버에 메일을 그대로 두고 여러 기기에서 동기화하여 읽음

HTTP의 `Redirect`(리다이렉션)는 서버가 클라이언트(웹 브라우저나 앱)에게 "요청한 리소스가 다른 주소로 옮겨갔으니, 안내하는 새 주소로 다시 요청해라"라고 지시하는 통신 메커니wma
## 1. 리다이렉트의 기본 동작 흐름 (3단계)
1. **최초 요청 (Request):** 클라이언트가 서버에 특정 URL로 요청을 보냄
2. **리다이렉트 응답 (Response):** 서버는 요청을 그대로 처리하는 대신, `3xx Status Code`와 함꼐 `Location` 헤더에 새 URL을 담아 응답함
3. **자동 재요청 (Follow Redirect):** 브라우저는 3xx 응답을 받으면 `Loaction`헤더에 적힌 주소로 새로운 요청을 다시 전송함

## 2. 대표적인 3xx 리다이렉션 상태 코드

|**상태 코드**|**명칭**|**설명**|**메소드 변경 여부**|
|---|---|---|---|
|**`301`**|**Moved Permanently**|리소스의 영구적인 이동. 검색 엔진(SEO)도 새 URL로 색인을 업데이트함.|GET으로 바뀔 수 있음|
|**`302`**|**Found**|임시 이동. 과거 표준이며, 전통적인 웹 애플리케이션이나 OAuth 등에서 가장 흔히 쓰임.|GET으로 바뀔 수 있음|
|**`303`**|**See Other**|요청을 처리한 후, 결과 페이지를 **강제로 `GET` 메소드로 요청**하도록 지시함. (Form 제출 후 재요청 방지 등에 사용)|**무조건 GET으로 변경**|
|**`307`**|**Temporary Redirect**|임시 이동. 302와 달리 **최초 요청의 HTTP 메소드(`POST` 등)와 Body를 그대로 유지**하여 재요청함.|**메소드 유지**|
|**`308`**|**Permanent Redirect**|영구 이동. 301과 달리 최초 요청의 HTTP 메소드와 Body를 그대로 유지함.|**메소드 유지**|

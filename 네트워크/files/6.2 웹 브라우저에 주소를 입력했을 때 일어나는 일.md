웹 브라우저 주소창에 `[https://www.google.com](https://www.google.com)`을 입력하고 엔터를 누르는 순간부터 화면이 렌더링될 때까지, **OSI 7계층 전체를 관통하는 통합 타임라인**입니다.

## 🌐 브라우저 주소 입력 시 일어나는 전체 타임라인

```
[사용자 엔터] ──► [URL 파싱 & HSTS] ──► [DNS 조회 (UDP/IP)] ──► [ARP (MAC 확보)]
     │
     ▼
[TCP 3-Way Handshake (L4)] ──► [SSL/TLS Handshake (L5-6)] ──► [HTTP GET 요청 (L7)]
     │
     ▼
[서버 응답 & 패킷 역캡슐화] ──► [브라우저 렌더링 (DOM/CSSOM)]
```

### Phase 1. 클라이언트 내부 처리 (L7 Application)

1. **URL 파싱 (URL Parsing):**
    
    - 브라우저는 입력된 문자열을 파싱합니다.
        
    - 프로토콜(`https://`), 도메인 이름(`[www.google.com](https://www.google.com)`), 포트 번호(HTTPS 기본값 `443`)를 분리합니다.
        
2. **HSTS 검사 (HTTP Strict Transport Security):**
    
    - 브라우저 내부 HSTS 목록을 확인하여, 해당 사이트가 HTTPS 강제 접속 대상인지 체크하고 필요시 `https://`로 자동 전환합니다.
        

### Phase 2. IP 주소 탐색 (DNS & ARP)

#### 1) DNS 조회 (Domain Name Resolution)

`[www.google.com](https://www.google.com)`이라는 호스트 이름을 L3 통신을 위한 **IP 주소**로 변환해야 합니다.

- **브라우저 & OS 캐시 확인:** 브라우저 캐시 $\rightarrow$ OS Hosts 파일 및 DNS 캐시 순으로 검색합니다.
    
- **재귀적 DNS 쿼리 (UDP Port 53 사용):**
    
    - 캐시에 없다면 OS의 Local DNS 서버(통신사 DNS)로 UDP 패킷을 보냅니다.
        
    - Local DNS는 **Root DNS $\rightarrow$ .com TLD DNS $\rightarrow$ google.com Authoritative DNS** 순으로 계층적(Iterative)으로 물어물어 final IP 주소(예: `142.250.207.78`)를 얻어옵니다.
        

#### 2) ARP (Address Resolution Protocol)

- **목적지 네트워크 판단:** 내 PC는 목적지 IP가 외부 네트워크(WAN)에 있음을 서브넷 마스크 연산으로 확인합니다.
    
- **게이트웨이 MAC 주소 확보:** 외부로 나가기 위해 **기본 게이트웨이(내 집 공유기)의 MAC 주소**가 필요합니다. ARP 캐시에 없다면 ARP Request(Broadcast)를 날려 공유기의 MAC 주소를 확보합니다.
    

### Phase 3. 캡슐화 (Encapsulation) & 전송 (L7 $\rightarrow$ L1)

목적지 IP와 차회 목적지(Next Hop) MAC 주소를 확보했으므로 OS의 네트워크 스택(TCP/IP Stack)이 패킷을 캡슐화합니다.

Plaintext

```
[ L7 App Data ]  (HTTP GET 요청 메시지 - 아직 송신 전, 연결부터 수립)
      │
      ▼  L4 (Transport): TCP Header 추가 (Src Port: 51234, Dst Port: 443, SYN Flag)
[ TCP Segment ]
      │
      ▼  L3 (Network): IP Header 추가 (Src IP: 내 공인 IP, Dst IP: 구글 IP)
[ IP Packet ]
      │
      ▼  L2 (Data Link): Ethernet Header 추가 (Src MAC: 내 MAC, Dst MAC: 공유기 MAC)
[ Frame ]
      │
      ▼  L1 (Physical): NIC(랜카드)를 통해 전기/광/무선 신호로 변환
[ 0101... Bit Stream ] ──► 랜선 / Wi-Fi 공기 중으로 쏘아 올림
```

### Phase 4. 네트워크망 이동 & 스위칭/라우팅 (L1 $\rightarrow$ L3)

1. **L1/L2 (스위치/공유기):**
    
    - 공유기는 L1 신호를 복원하여 L2 프레임의 Dst MAC(자신)을 확인하고 수신합니다.
        
2. **L3 (라우팅 & NAT):**
    
    - 공유기는 NAT(네트워크 주소 변환)를 거쳐 출발지 사설 IP를 **공인 IP**로 바꿉니다.
        
    - L2 헤더의 Dst MAC을 **통신사(ISP) 첫 라우터 MAC**으로 덮어쓰고 내보냅니다.
        
3. **WAN & 해저 광케이블 경유 (Hop-by-Hop):**
    
    - 수십 개의 광역 라우터를 거칩니다. 라우터들은 L3의 Dst IP(구글)를 보며 라우팅 경로를 정하고, **L2 MAC 주소만 계속 다음 라우터의 MAC 주소로 덮어쓰며** 이동합니다.
        
4. **구글 데이터센터 도착:**
    
    - 구글 최전방 라우터가 패킷을 받아, ARP를 통해 내부 **구글 L7 로드밸런서/웹 서버의 실제 MAC 주소**를 적어 최종 서버로 전달합니다.
        

### Phase 5. 세션 수립 & 암호화 채널 연결 (L4 & L5-L6)

#### 1) TCP 3-Way Handshake (L4 Transport)

신뢰성 있는 데이터 송수신을 위해 서버와 **TCP 커넥션을 수립**합니다.

```
Client                                  Server
  │ ─── 1. SYN (Seq=X) ───────────────► │
  │ ◄── 2. SYN-ACK (Seq=Y, Ack=X+1) ── │
  │ ─── 3. ACK (Ack=Y+1) ─────────────► │ (TCP 연결 완료, ESTABLISHED)
```

#### 2) SSL/TLS Handshake (L5 Session / L6 Presentation)

HTTPS 통신을 위해 **대칭키(Session Key)를 안전하게 교환**합니다.

1. **Client Hello:** 지원하는 TLS 버전, Cipher Suite, `Client Random` 전송
    
2. **Server Hello & Certificate:** 선택된 Cipher Suite, `Server Random`, **CA 인증서(서버 공개키)** 전송
    
3. **인증서 검증:** 브라우저가 내장된 Root CA 공개키로 서버 신원 검증
    
4. **Key Exchange:** 클라이언트가 `Premaster Secret`을 생성 후 **서버 공개키로 암호화**하여 전송
    
5. **세션키 생성:** 양측이 `Client Random + Server Random + Premaster Secret`을 조합해 **대칭키(Session Key)** 복제
    
6. **Finished:** 핸드셰이크 완료 및 암호화 통신 준비 완료
    

### Phase 6. HTTP 요청과 응답 (L7 Application)

1. **HTTP Request 전송 (L7):**
    
    - 브라우저가 비로소 진짜 원했던 암호화된 HTTP 요청 메시지를 구성하여 보냅니다.
        
    - `GET / HTTP/1.1`, `Host: [www.google.com](https://www.google.com)`, `User-Agent: Chrome/...`
        
2. **서버 처리 & Response 반환 (L7):**
    
    - 구글 웹 서버가 암호화된 요청을 복호화하여 처리하고, 암호화된 HTTP 응답 메시지를 반환합니다.
        
    - `HTTP/1.1 200 OK`, `Content-Type: text/html`, HTML 본문 데이터
        

### Phase 7. 패킷 역캡슐화 & 브라우저 렌더링

#### 1) 클라이언트 OS의 역캡슐화 (Decapsulation)

- **L1 $\rightarrow$ L2:** 랜카드가 신호를 받아 Ethernet 프레임 수신 (내 MAC 확인 후 L2 헤더 제거)
    
- **L2 $\rightarrow$ L3:** IP 패킷 확인 (내 IP 확인 후 L3 헤더 제거)
    
- **L3 $\rightarrow$ L4:** TCP 세그먼트 확인 (포트 번호 `51234` 확인 후 수신 버퍼로 이동, L4 헤더 제거)
    
- **L4 $\rightarrow$ L5-L6:** TLS 대칭키로 데이터 복호화
    
- **L6 $\rightarrow$ L7:** 순수한 HTML/CSS/JS 데이터 덩어리를 **브라우저 응용 프로그램**에 전달
    

#### 2) 브라우저 렌더링 엔진 작동 (Critical Rendering Path)

1. **HTML 파싱 $\rightarrow$ DOM Tree** 생성
    
2. **CSS 파싱 $\rightarrow$ CSSOM Tree** 생성
    
3. **Render Tree** 구축 (DOM + CSSOM 결합)
    
4. **Layout (Reflow):** 요소들의 정확한 위치와 크기 계산
    
5. **Paint (Repaint):** 화면에 실제 색상과 레이어를 그림 (픽셀화)
    
6. **JS 실행:** 필요시 V8 엔진이 JavaScript 코드를 파싱 및 실행하여 동적 화면 변경

## 1. 3계층 - 네트워크 계층 (Network Layer)의 필요성

네트워크 계층(L3)은 서로 다른 네트워크(Subnet)에 존재하는 출발지 호스트부터 최종 목적지 호스트까지(Host-to-Host) 패킷의 종단 간 전송과 최적 경로 탐색(Routing)을 수행하는 계층입니다.
L2(스위치)만으로는 전 세계 인터넷 통신이 불가능하며, L3가 반드시 필요한 이유는 다음과 같습니다:

- **서로 다른 네트워크 간 통신 (Inter-Networking)**
    - L2 스위치는 같은 동네(LAN) 내부 통신만 담당합니다.
    - **L3 적용 시:** IP 주소를 기반으로 서로 다른 네트워크(예: 우리 집 ➔ 구글 서버)를 연결해 주는 다리 역할을 합니다.
        
- **최적 경로 탐색 (Routing)**
    - 목적지까지 갈 수 있는 수많은 길(링크) 중 **가장 빠르고 효율적인 경로를 계산**하여 패킷을 전달합니다.
        
- **브로드캐스트 경계 형성 (Broadcast Containment)**
    - L3 장비(라우터)는 브로드캐스트 패킷을 차단하여 **전 세계 인터넷망이 방송 패킷으로 마비되는 것을 방지합니다.


## 2. MAC 주소만으로 글로벌 통신이 불가능한 이유 (위치 정보의 부재)

전 세계 모든 랜카드에는 고유한 MAC 주소가 있지만, MAC 주소만으로는 전 세계 인터넷 통신을 할 수 없습니다.
### 💡 주민등록번호 vs 도로명 주소 메커니즘

- **MAC 주소 (주민등록번호):**
    - 기기를 유일하게 식별하지만 **"위치 정보"가 없습니다.**
    - 택배 상자에 주민번호만 적혀있다면, 전 세계 모든 집을 일일이 방문(브로드캐스트)해서 찾아야 하므로 인터넷이 마비됩니다.
        
- **IP 주소 (도로명 주소):**
    - 계층적 구조 (`국가` ➔ `도시` ➔ `도로` ➔ `건물번호`)를 가집니다.
    - 라우터들은 수십억 대 기기의 위치를 다 외울 필요 없이, 커다란 동네 단위(`Network ID`)로 묶어서 효율적으로 경로를 찾아갑니다.

## 🏷️ IP 주소의 계층적 구조 메커니즘

네트워크 계층에서는 패킷을 효율적으로 전달하기 위해 IP 주소를 **두 부분으로 나누어 관리**합니다.

```
[ IP 주소 구조 (예: 192.168.0.15) ]
┌──────────────────────────────────────┬──────────────────────────────────┐
│          네트워크 ID (Network ID)      │          호스트 ID (Host ID)      │
│               (192.168.0)            │                 (.15)            │
└──────────────────────────────────────┴──────────────────────────────────┘
                   ▲                                       ▲
         [ 어느 동네/네트워크인가? ]               [ 그 동네의 몇 번 기기인가? ]
```

- **네트워크 ID (Network ID):**
    - 라우터가 목적지 동네까지 길을 찾아갈 때(Routing) 사용하는 **대역 주소**입니다.
        
- **호스트 ID (Host ID):**
    - 목적지 동네에 도착한 후, **해당 내부 네트워크 안에서 특정 기기를 식별**할 때 사용하는 주소입니다.

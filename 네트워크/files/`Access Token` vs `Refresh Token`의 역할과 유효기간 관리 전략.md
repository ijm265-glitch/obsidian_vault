JWT와 같은 토큰 기반 인증 체계에서 하나의 토큰만 사용하면 "유효기간을 길게 잡으면 탈취 시 위험하고, 짧게 잡으면 사용자가 자꾸 재로그인해야 한다"는 Dilemma에 빠집니다.

이 문제를 해결하기 위해 도입된 것이 **Access Token**과 **Refresh Token**의 2중 토큰 체계입니다.

### 1. 두 토큰의 역할 분담

|**구분**|**Access Token (액세스 토큰)**|**Refresh Token (리프레시 토큰)**|
|---|---|---|
|**주 목적**|**리소스 접근 권한 인증**|**Access Token 재발급**|
|**사용처**|모든 API 요청 헤더 (`Authorization`)|토큰 재발급 전용 API 요청 시에만 사용|
|**유효기간**|**매우 짧음** (예: 15분 ~ 2시간)|**상대적으로 긺** (예: 7일 ~ 2주)|
|**저장 위치**|메모리(변수) 또는 Cookie|**안전한 저장소** (HttpOnly Cookie, DB 등)|
|**서버 저장 여부**|**저장 안 함** (Stateless 검증)|**서버/DB에 저장 및 관리** (Blacklist/Whitelisting)|

### 2. 기본 동작 및 재발급 흐름 (RTR 기법)

1. **평상시 API 호출:** 클라이언트는 수명이 짧은 `Access Token`을 헤더에 실어 API를 호출합니다.
    
2. **Access Token 만료 시:** 서버는 `401 Unauthorized`를 응답합니다.
    
3. **토큰 재발급 요청:** 클라이언트(브라우저/앱)는 사용자가 모르게 백그라운드에서 `Refresh Token`을 실어 재발급 API(`/api/auth/refresh`)를 호출합니다.
    
4. **검증 및 재발급:** 서버는 `Refresh Token`이 유효한지(DB 대조 및 만료 여부) 확인 후, **새로운 Access Token**을 발급해 줍니다. 사용자는 로그인 화면으로 튕기지 않고 서비스를 계속 이용합니다.
    
### 3. 유효기간 관리 및 보안 전략

#### ① Access Token은 짧게, Refresh Token은 적절하게

- **Access Token:** 보통 **15분 ~ 30분**으로 매우 짧게 설정합니다. 혹여나 네트워크 스니핑 등으로 탈취당하더라도 피해를 최소화하기 위함입니다.
    
- **Refresh Token:** 보통 **7일 ~ 14일** 정도로 설정합니다. 너무 길면 관리 부담이 커지고, 너무 짧으면 사용자가 자주 로그아웃됩니다.
    
#### ② 토큰 저장소 분리 (클라이언트 측)

- **Access Token:** XSS(Cross-Site Scripting) 공격을 받아도 탈취당하지 않도록 자바스크립트 내 메모리 변수(React State 등)에 저장합니다. (페이지 리프레시 시 사라지면 Refresh Token으로 다시 받아옴)
    
- **Refresh Token:** JavaScript로 접근할 수 없도록 `HttpOnly` 및 `Secure` 옵션이 설정된 쿠키(Cookie)에 저장합니다.
    
#### ③ RTR (Refresh Token Rotation) 기법 적용 ★★★

Refresh Token 역시 탈취될 위험이 있습니다. 이를 막기 위해 현대 웹 아키텍처에서는 **RTR 패턴**을 필수로 적용합니다.

- **원리:** Access Token을 재발급할 때 **Refresh Token도 함께 일회성으로 폐기하고 새로 발급**합니다.
    
- **보안 효과 (탈취 감지):**
    
    - 만약 해커가 탈취한 옛날 Refresh Token으로 재발급을 시도하면, 이미 사용된 토큰이므로 서버가 "토큰 탈취 발생!"으로 판단합니다.
        
    - 서버는 즉시 해당 사용자의 모든 Refresh Token을 DB에서 무효화(Blacklist)시켜 버립니다. 결과적으로 진짜 사용자도 로그아웃되지만, 해커의 접근을 완벽히 차단할 수 있습니다.
        
#### ④ Sliding Sessions (유효기간 연장)

- 사용자가 지속적으로 서비스를 이용하고 있다면, Refresh Token의 만료 기간을 마지막 접속 시점부터 다시 7일/14일로 자동 연장해 주는 방식입니다.
    
- 사용자가 자주 서비스를 방문하면 **로그아웃되지 않고 끊김 없는 사용자 경험**을 제공할 수 있습니다.

### 1. IP(건물 주소) + Port(방 번호)의 개념

한 대의 컴퓨터(IP: `192.168.1.12`)에서는 웹 브라우저(Chrome), 카카오톡, 게임, 음악 스트리밍 등 **여러 개의 프로세스**가 동시에 인터넷 통신을 합니다.

수신된 패킷이 컴퓨터 랜카드에 도착했을 때, 운영체제(OS)는 이 데이터가 대체 누구 것인지 알아야 합니다.
- **IP 주소:** 전 세계 수많은 컴퓨터 중 "어느 컴퓨터(건물)인가?"를 식별합니다.
- **Port 번호:** 그 컴퓨터 내부에서 동작 중인 "어느 프로세스(방/호수)로 들어갈 데이터인가?"를 식별합니다.
    
```
  [ 목적지 패킷 ]
  IP   : 223.130.192.247  --->  해당 IP를 가진 '서버 건물' 도착
  Port : 80               --->  건물 내부의 '80호실(웹 서버 프로세스)'로 배달!
```

- **소켓(Socket) 쌍:** 통신이 이루어질 때는 항상 `[출발지 IP : 출발지 Port] ↔ [목적지 IP : 목적지 Port]`의 4가지 조합(4-Tuple)으로 네트워크 연결을 고유하게 식별합니다.
    
### 2. 포트 번호의 범위와 3가지 분류 (0 ~ 65535)

포트 번호는 **16비트(Bit)** 정수로 표현되므로, 총 **0번부터 65535번**까지 존재합니다. IANA(인터넷 할당 번호 관리기관)는 이 번호대를 역할에 따라 3가지 구역으로 나누어 관리합니다.

#### ① Well-Known Ports (잘 알려진 포트: `0` ~ `1023`)

- **특징:** 서버 측에서 동작하는 **가장 대표적이고 표준적인 통신 프로토콜들**에 미리 예약되어 있는 포트입니다.
- **보안:** 시스템의 중요 서비스들이 사용하므로, 리눅스/유닉스 계열 OS에서는 관리자 권한(root/sudo)이 있어야만 이 영역의 포트를 열 수 있습니다.
- **주요 번호:**
    - `20`, `21`: **FTP** (파일 전송)
    - `22`: **SSH** (원격 리눅스 접속)
    - `23`: **Telnet** (암호화 안 되는 원격 접속)
    - `25`: **SMTP** (메일 발송)
    - `53`: **DNS** (도메인 주소 변환)
    - `80`: **HTTP** (웹 암호화 미적용)
    - `443`: **HTTPS** (웹 암호화 적용)
#### ② Registered Ports (등록된 포트: `1024` ~ `49151`)

- **특징:** 특정 기업이나 상용 소프트웨어 개발사가 자신의 애플리케이션 통신용으로 IANA에 **공식 등록하여 사용하는 포트**입니다.
- **주요 번호:**
    - `1433`: **MS SQL** Server
    - `1521`: **Oracle** Database
    - `3306`: **MySQL / MariaDB**
    - `5432`: **PostgreSQL**
    - `6379`: **Redis** (In-memory DB)
    - `8080` / `8000`: **웹 개발용 대체 포트** (Spring, Django, Tomcat 등)
        

#### ③ Dynamic / Private / Ephemeral Ports (동적/임시 포트: `49152` ~ `65535`)

- **특징:** 서버가 아니라 클라이언트(내 PC, 스마트폰)가 브라우저 등을 열고 외부 서버로 접속할 때, **OS가 임시로 아무 번호나 하나 쥐여주는 포트**입니다.
    
- **동작 예시:**
    
    - 내가 크롬 브라우저로 구글(`8.8.8.8:53` 또는 `142.250.X.X:443`)에 접속합니다.
    - 내 OS는 남는 동적 포트 중 하나(예: `51234`)를 난수로 골라 출발지 포트로 설정합니다.
    - 구글 서버가 응답을 돌려줄 때 바로 내 PC의 `51234`번 포트로 패킷을 쏴주고, 브라우저 탭이 닫히면 OS는 이 포트 번호를 다시 회수합니다.

## 1. MAC 주소(Media Access Control Address)의 정의
- **정의:** LAN 카드(NIC, Network Interface Card) 제조 시 하드웨어에 영구적으로 익혀지는 **48비트(6바이트) 크기의 물리적 고유 식별 주소**입니다.
- **별칭:** BIA(Burned-In Address), 물리 주소(Physical Address), 이더넷 주소(Ethernet Address)
- **특징:** OSI 2계층(데이터 링크 계층)에서 **동일한 서브넷(LAN) 내의 바로 옆 노드 간 식별 및 프레임 전송**을 위해 사용됩니다. IP 주소(3계층)가 변할 수 있는 '상점의 주소/위치'라면, MAC 주소는 '사람의 주민등록번호/지문'에 비유할 수 있습니다.
    

## 2. MAC 주소의 표기법
- **16진수(Hexadecimal) 표기:** 48비트의 이진수 데이터를 사람이 읽기 쉽게 **8비트(1바이트)씩 6개 구역으로 나누어 16진수**로 표기합니다.
- **표기 형태 예시:**
    - `00:1A:2B:3C:4D:5E` (콜론 구분)
    - `00-1A-2B-3C-4D-5E` (하이픈 구분)
    - `001A.2B3C.4D5E` (시스코 방식: 16비트씩 마침표 구분)

## 3. MAC 주소의 48비트 구조: OUI와 Vendor Identification
48비트 MAC 주소는 전 세계에서 중복되지 않도록 IEEE(전기전자공학자학회)의 엄격한 관리하에 **상위 24비트**와 **하위 24비트**로 정교하게 분할되어 할당됩니다.

```
[ 48비트 (6바이트) MAC 주소 구조 ]

┌─────────────────────────┬─────────────────────────┐
│     상위 24 비트        │     하위 24 비트        │
│   OUI (제조사 식별자)   │ Vendor ID (시리얼 번호) │
└─────────────────────────┴─────────────────────────┘
  00 : 1A : 2B             3C : 4D : 5E
  ▲
  └─ b0: Unicast / Multicast 비트
     b1: Global / Local 비트
```

### 3.1 상위 24비트: OUI (Organizationally Unique Identifier)
- **정의:** IEEE 기구가 랜카드 제조 회사(삼성, Intel, Realtek, Cisco 등)에 유료로 할당하는 **제조업체 고유 식별 코드**입니다.
- **역할:** MAC 주소의 앞 3바이트(24비트)만 확인하면 해당 장비를 만든 제조 회사가 어디인지 즉시 조회할 수 있습니다. (예: `00:00:0C` ➔ Cisco, `00:1A:2B` ➔ Ayecom 등)
### 3.2 하위 24비트: Vendor Identification (시리얼 번호 / UAA)
- **정의:** OUI를 할당받은 각 제조사가 자신이 생산하는 LAN 카드 제품마다 일련번호 형태로 부여하는 고유 일련번호(Serial Number)입니다.
- **역할:** $2^{24} = 16,777,216$개의 서로 다른 고유 주소를 하나의 OUI당 생산할 수 있습니다.
    

## 4. OUI의 첫 번째 바이트에 숨겨진 제어 비트 (LGB / I/G 비트)
상위 24비트 중 **가장 첫 번째 바이트의 최하위 2개 비트**는 네트워크 수신 장비가 주소의 성격을 판별하는 매우 특별한 용도로 약속되어 있습니다.

```
첫 번째 바이트의 8비트 구조: [ b7 b6 b5 b4 b3 b2 | b1 | b0 ]
                                                   │    │
                                 Global / Local ───┘    └── Unicast / Multicast
```

1. **b0 (I/G 비트 - Individual / Group):**
    - `0`: **단일 호스트(Unicast)** 대상 프레임 (1:1 통신)
    - `1`: **그룹/전체(Multicast / Broadcast)** 대상 프레임 (1:N 통신)
    - _(참고: 브로드캐스트 주소인 `FF:FF:FF:FF:FF:FF`는 모든 비트가 1이므로 b0 비트 역시 1입니다.)_
2. **b1 (G/L 비트 - Global / Local):**
    - `0`: IEEE가 공식 할당한 **전 세계 고유 주소 (UAA, Universally Administered Address)**
    - `1`: 관리자가 소프트웨어적으로 임의 수정한 **지역 관리 주소 (LAA, Locally Administered Address)** (예: MAC 주소 스푸핑/수정 시 사용)

## 4. MAC 주소의 변경(스푸핑/가변성) 원리
원칙적으로 하드웨어 칩에 새겨진 MAC 주소는 전 세계 고유값(BIA)이지만, **실제 통신에서는 소프트웨어적으로 가짜 주소를 사용하거나 임의로 변경(Spoofing)하는 것이 가능**합니다.
```
[공장 출고 칩 (ROM)] ───► (부팅 시 읽기) ───► [OS 메모리 / 랜카드 필터 (RAM)]
   "00:1A:2B:3C:4D:5E"                          "00:1A:2B:3C:4D:5E" (정품 UAA, b1=0)
   (물리적 고유값)                                      │
                                             (사용자/OS가 임의 변경)
                                                        ▼
                                             "AA:BB:CC:DD:EE:FF" (가짜 LAA, b1=1)
                                             ➔ 송수신 시 이 가짜 주소를 활성 사용!
```
### 4.1 왜 가짜 MAC 주소로 통신(송수신)이 가능한가?
1. **하드웨어(ROM) vs 소프트웨어(RAM):**
    - 랜카드 ROM에 새겨진 주소는 변하지 않지만, OS가 부팅되면 이 주소를 메모리(RAM)로 읽어와 사용합니다.
    - 네트워크 드라이버 설정(장치 관리자 등)에서 MAC 주소를 변경하면, **메모리상의 주소(Active Address)와 랜카드의 수신 필터 주소가 동시에 교체**됩니다.
        
2. **양방향 통신 성립 원리:**
    - **송신:** 가짜 MAC 주소를 출발지로 적어 프레임을 쏩니다.
    - **상대방/스위치:** 가짜 MAC 주소를 해당 포트의 주소로 인식하고 답장을 보냅니다.
    - **수신:** 랜카드는 현재 활성화된 가짜 MAC 주소를 자기 주소로 인식하므로 **답장 프레임을 정상 수신**합니다.
        
3. **주요 활용 및 적용 사례:**
    - **MAC 스푸핑 (Spoofing):** 보안 공격 또는 Wi-Fi 접근 제어 우회용으로 신원 기만.
    - **랜덤 MAC (Randomized MAC):** 아이폰/갤럭시 등 현대 스마트폰 OS가 공공 Wi-Fi 추적을 막기 위해 연결 시마다 가짜 주소(LAA, `b1=1`)를 무작위로 생성하여 사용함.
## 5. 핵심 요약

|**구분**|**하드웨어 MAC (UAA / BIA)**|**소프트웨어 MAC (LAA / Spoofed)**|
|---|---|---|
|**저장 위치**|랜카드 internal ROM/EEPROM 칩|OS 메모리 (RAM) / 랜카드 수신 필터|
|**변경 여부**|**불가** (공장 출고 고유값)|**가능** (사용자/OS 임의 설정 가능)|
|**G/L 비트 (`b1`)**|**`0`** (Global / 정품 고유 주소)|**`1`** (Local / 소프트웨어 수정 주소)|
|**사용 목적**|장비의 물리적 근본 식별|사생활 보호(랜덤 MAC), 보안 테스트 등|

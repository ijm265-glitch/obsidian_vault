## 1. 서브넷 마스크(Subnet Mask)와 비트 연산
클래스풀(Classful) 방식의 IP 낭비를 막기 위해 등장한 **서브넷 마스크**는 32비트 IP 주소에서 **어디까지가 네트워크 ID이고, 어디서부터가 호스트 ID인지를 정확히 잘라주는 '자' 역할**을 합니다.

### 💡 AND 비트 연산 메커니즘
컴퓨터는 자신의 IP 주소와 서브넷 마스크를 **`AND` 비트 연산**하여 자신이 속한 네트워크 대표 주소(Network ID)를 추출해 냅니다.
- **AND 연산 규칙:** 둘 다 `1`일 때만 `1`, 하나라도 `0`이면 `0`
- **예시:** IP가 `192.168.0.15`이고, 서브넷 마스크가 `255.255.255.0`일 때
    

$$\begin{array}{rll} \text{IP 주소 (192.168.0.15):} & \mathtt{11000000.10101000.00000000.00001111} \\ \mathbf{AND} \quad \text{서브넷 마스크 (255.255.255.0):} & \mathtt{11111111.11111111.11111111.00000000} \\\hline \text{네트워크 대표 주소 (192.168.0.0):} & \mathtt{11000000.10101000.00000000.00000000} \end{array}$$

- 서브넷 마스크의 `1` 영역 ➔ **Network ID** (그대로 유지)
- 서브넷 마스크의 `0` 영역 ➔ **Host ID** (모두 0으로 덮어씀)

## 2. CIDR (Classless Inter-Domain Routing) 표기법
기존의 A, B, C 클래스 개념을 부수고, **비트 단위로 네트워크 경계를 자유롭게 쪼개기 위해 도입된 표준 표기법**입니다.
IP 주소 뒤에 사선(`/`)을 붙이고 네트워크 ID로 사용할 비트 수(서브넷 마스크에서 연속된 1의 개수)를 적어줍니다.
```
[ IP 주소 / 서브넷 마스크 1의 개수 ]

 예) 192.168.0.15/24
     └── /24 ➔ 서브넷 마스크의 앞에서부터 24개 비트가 '1'이라는 뜻!
         (11111111.11111111.11111111.00000000 ➔ 255.255.255.0)
```

### 🏷️ 자주 쓰이는 CIDR 비트 예시
- **/24:** `255.255.255.0` (호스트 영역 8비트 ➔ 총 $2^8 = 256$개 주소)
- **/25:** `255.255.255.128` (호스트 영역 7비트 ➔ 총 $2^7 = 128$개 주소)
- **/26:** `255.255.255.192` (호스트 영역 6비트 ➔ 총 $2^6 = 64$개 주소)
## 3. 할당 불가능한 주소: $2^n - 2$ 법칙

하나의 서브넷(네트워크)이 구성되었을 때, 확보된 전체 IP 개수($2^n$, 여기서 $n$은 호스트 비트 수) 중에서 **2개 주소는 PC나 ESP32 같은 개별 기기(호스트)에 할당할 수 없습니다.**

```
[ 예: 192.168.0.0/24 대역 (총 256개) ]

 192.168.0.0   ──► 네트워크 대표 주소 (Host 비트가 모두 0) [할당 불가]
 192.168.0.1   ──┐
 192.168.0.2     │
     ...         ├─► 실제 기기에 할당 가능한 유효 IP (254개)
 192.168.0.254 ──┘
 192.168.0.255 ──► 브로드캐스트 주소 (Host 비트가 모두 1)   [할당 불가]
```

1. **네트워크 대표 주소 (Network Address)**
    - **조건:** 호스트 ID 비트가 전부 `0`인 주소 (예: `192.168.0.0`)
    - **역할:** "이 동네 전체"를 대표하는 이름 표지판 역할을 하므로 기기에 부여할 수 없습니다.
        
2. **브로드캐스트 주소 (Broadcast Address)**
    - **조건:** 호스트 ID 비트가 전부 `1`인 주소 (예: `192.168.0.255`)
    - **역할:** 이 주소로 패킷을 쏘면 해당 서브넷 안의 모든 기기에게 외치는 방송 패킷이 되므로 기기에 부여할 수 없습니다.
        

> 💡 **실제 이용 가능한 호스트 수 공식:**
$$\text{할당 가능 IP 수} = 2^n - 2 \quad (n = \text{호스트 비트 수})$$

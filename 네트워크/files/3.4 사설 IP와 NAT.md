## 1. IPv4 고갈 문제와 사설 IP 대역
약 42억 개의 IPv4 주소가 인터넷 인구 증가로 조기 고갈될 위기에 처하자, 전 세계 네트워크 기구(IETF)는 "인터넷 전용 주소(공인 IP)"와 "내부망 전용 주소(사설 IP)"를 엄격히 분리하는 약속(RFC 1918)을 만들었습니다.

### 💡 사설 IP 대역 (Private IP Ranges)
아래 대역은 외부 인터넷망에서 **중복 사용이 허용된 내부 전용 주소**로, 인터넷 라우터에서 라우팅되지 않고 차단됩니다.
- **Class A 대역:** `10.0.0.0` ~ `10.255.255.255` (`10.0.0.0/8`) ➔ 대규모 기업 내부망
- **Class B 대역:** `172.16.0.0` ~ `172.31.255.255` (`172.16.0.0/12`) ➔ 중규모 조직
- **Class C 대역:** `192.168.0.0` ~ `192.168.255.255` (`192.168.0.0/16`) ➔ **가정용 공유기, ESP32, 일반 사무실**
    

## 2. 공인 IP vs 사설 IP 비교
```
  [ 외부 인터넷 세상 ] ── (공인 IP: 211.200.10.5) ── [ 공유기 (NAT) ] ── (사설 IP: 192.168.0.2) ── [ 내 PC ]
                                                               └── (사설 IP: 192.168.0.3) ── [ ESP32 ]
```

|**구분**|**공인 IP (Public IP)**|**사설 IP (Private IP)**|
|---|---|---|
|**주소 고유성**|**전 세계에서 유일**함|**내부 네트워크(LAN) 안에서만 고유**함 (타인의 집과 중복 가능)|
|**할당 주체**|ISP (통신사: KT, SKT, LGU+)|**공유기(DHCP)** 또는 사용자가 직접 고정 할당|
|**인터넷 통신**|외부 인터넷 직접 통신 **가능**|외부 인터넷 직접 통신 **불가능** (NAT 거쳐야 함)|
|**접근성**|외부 어디서나 접속 가능|**외부 인터넷에서 직접 접근 불가능** (보안성 확보)|

## 3. NAT 및 PAT(Port Address Translation) 작동 원리

공유기는 단 1개의 **공인 IP**만 통신사로부터 할당받은 뒤, 내부의 수많은 기기(PC, 스마트폰, ESP32 등)가 사설 IP를 가지고 동시에 인터넷을 이용할 수 있도록 주소를 변환해 줍니다.

> **NAT (Network Address Translation):** IP 주소를 변환하는 기술
> 
> **PAT (Port Address Translation):** L4 계층의 **'포트 번호'**를 함께 활용하여 **공인 IP 1개로 사설 IP 여러 개를 구분**해 내는 N:1 주소 변환 기법 (실제 공유기가 사용하는 핵심 기술!)

### 🏷️ PAT 작동 메커니즘 (가정용 공유기 원리)

내 PC(`192.168.0.2`)와 ESP32(`192.168.0.3`)가 동시에 구글 서버(`142.250.X.X:80`)로 요청을 보낼 때 공유기가 매핑하는 과정입니다.
```
[ 1. 나갈 때 (Outbound) ]
  - PC 요청:     [출발지 192.168.0.2 : 50001] ──► [공유기] ──► [출발지 211.200.10.5 : 10001] 변환 후 구글로 송신
  - ESP32 요청:  [출발지 192.168.0.3 : 50001] ──► [공유기] ──► [출발지 211.200.10.5 : 10002] 변환 후 구글로 송신

[ 공유기 내부 PAT 변환 테이블 (NAT Table) ]
┌─────────────────────────────┬─────────────────────────────┐
│    내부 사설 IP : 포트      │    외부 변환 공인 IP : 포트  │
├─────────────────────────────┼─────────────────────────────┤
│    192.168.0.2 : 50001      │    211.200.10.5 : 10001    │ (PC 매핑)
│    192.168.0.3 : 50001      │    211.200.10.5 : 10002    │ (ESP32 매핑)
└─────────────────────────────┴─────────────────────────────┘

[ 2. 돌아올 때 (Inbound) ]
  - 구글의 응답 패킷: [목적지 211.200.10.5 : 10001] ➔ 공유기 도착!
  - 공유기의 동작:    NAT 테이블 조회! "아, 10001번 포트로 온 거니까 [192.168.0.2 : 50001] PC한테 돌려줘야지!"
```

1. **주소/포트 변환 (Outbound):**
    내부 기기가 패킷을 보낼 때, 공유기는 패킷의 출발지 IP를 **공유기의 공인 IP**로 바꾸고, 임의의 외부 포트 번호(예: `10001`, `10002`)를 새로 부여하여 내부 사설 IP와 매핑한 뒤 NAT 테이블에 기록합니다.
    
2. **패킷 전달 (Inbound):**
    외부 서버가 응답을 보내면, 공유기는 들어오는 **목적지 포트 번호**를 NAT 테이블에서 조회하여 **원래 요청했던 사설 IP와 내부 포트로 패킷을 정확히 되돌려줍니다.**

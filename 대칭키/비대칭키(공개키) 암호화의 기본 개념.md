**비대칭키(공개키) 암호화**는 데이터를 암호화할 때 쓰는 키와, 복호화(암호를 푸는 것)할 때 쓰는 **키가 서로 다른(비대칭인) 암호화 방식**입니다.

하나의 키로 문을 잠그고 열던 기존의 열쇠(대칭키) 방식에서 벗어나, **쌍을 이루는 두 개의 키**를 만들어 사용하는 것이 핵심입니다.

### 1. 두 개의 키: 공개키와 개인키

비대칭키 알고리즘을 사용하면 수학적으로 밀접하게 연계된 한 쌍의 키(Pair)가 생성됩니다.

- **공개키 (Public Key):** 누구나 볼 수 있도록 세상에 공개하는 키입니다.
    
- **개인키 (Private Key / 비밀키):** 오직 소유자 자신만 안전하게 보관해야 하는 키입니다.
    

이 두 키는 "A 키로 암호화한 데이터는 오직 B 키로만 풀 수 있다"는 일방향 수학적 성질을 가집니다.

Plaintext

```
[ 데이터 ] --- (공개키로 암호화) ---> [ 암호문 ]
[ 암호문 ] --- (개인키로 복호화) ---> [ 데이터 ]
```

### 2. 비대칭키의 2가지 핵심 활용 목적

비대칭키는 어느 키로 암호화를 시작하느냐에 따라 **사용 목적**이 완전히 달라집니다.

#### ① 데이터 기밀성 보장 (암호화)

> **"누구나 나에게 비밀 편지를 보낼 수 있지만, 읽는 건 나만 가능하게 한다."**

- **방식:** 송신자가 수신자의 **공개키**로 데이터를 암호화하여 전송합니다.
    
- **결과:** 세상 모든 사람이 이 암호문을 얻더라도, 이를 풀 수 있는 것은 수신자의 **개인키**뿐입니다.
    
- **용도:** HTTPS 통신 초기의 대칭키(세션키) 안전한 교환, 비밀 정보 전달.
    

#### ② 신원 증명 및 위변조 방지 (전자서명 / Authentication)

> **"이 메시지는 반드시 내가 작성했고, 중간에 수정되지 않았음을 증명한다."**

- **방식:** 발신자가 자신의 **개인키**로 데이터를 암호화(서명)하여 전송합니다.
    
- **결과:** 수신자가 발신자의 **공개키**로 복호화에 성공한다면, "이 데이터는 발신자의 개인키로 만들어진 것이 확실하다"는 점이 증명됩니다.
    
- **용도:** 전자서명, SSL/TLS 인증서 검증, JWT Signature 검증.
    

### 3. 대칭키 방식과의 직관적 비교

|**구분**|**대칭키 (Symmetric Key)**|**비대칭키 (Asymmetric Key)**|
|---|---|---|
|**키 개수**|1개 (암복호화 키 동일)|2개 (공개키 + 개인키)|
|**비유**|자물쇠와 열쇠 1개|열린 금고(공개키)와 그 금고의 열쇠(개인키)|
|**장점**|연산 속도가 매우 빠름|**키 전달 문제 해결** (공개키는 노출되어도 안전)|
|**단점**|키를 상대에게 전달할 때 탈취 위험|연산 속도가 상대적으로 매우 느림 (복잡한 수학 계산)|

### 4. 핵심 정리 및 웹/OAuth에서의 역할

비대칭키의 가장 큰 의의는 "안전하지 않은 인터넷 망에서 상대방과 사전에 비밀을 공유하지 않고도 안전하게 통신을 시작할 수 있게 했다"는 점에 있습니다.

실제 웹(HTTPS)이나 OAuth 환경에서는 비대칭키의 **느린 속도**라는 단점을 극복하기 위해 다음과 같이 조합하여 사용합니다:

1. **비대칭키**를 사용해 상대방의 신원을 확인하고, 속도가 빠른 대칭키(세션 키)를 안전하게 나누어 가집니다.
    
2. 이후 실제 대용량 데이터 통신은 전달받은 **대칭키**로 빠르게 수행합니다.
    
3. OAuth의 **JWT(JSON Web Token)** 검증 시, 인증 서버가 발급한 토큰이 진짜인지 확인할 때 인증 서버의 **공개키로 전자서명을 검증**합니다.

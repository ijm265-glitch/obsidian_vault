## 프로세스
메모리에 올라가 실제로 실행되고 있는 독립적인 프로그램 단위
__구조__ 
- Code : 코드가 저장됨
- Data : 전역 변수가 저장됨
- Heap : 동적 할당용
- Stack : 임시 데이터용
![[Pasted image 20260711220047.png|176]]
3개의 스레드가 생성된 물리적 메모리의 구조
Heap은 낮은 메모리 주소에서 올라가고
Stack은 높은 메모리 주소에서 낮아진다
## 스레드
하나의 프로세스 내부에서 실제로 작업을 수행하는 구체적인 실행 흐름
__공유__ : Code, Data, Heap
__비공유__ : Stack (각자의 작업 흐름을 가지고 있어야 하므로)

## 가상메모리
과거에는 프로세스가 직접 RAM의 물리주소에 접근하고 읽고 쓰기를 하였으나
이 경우 2개의 서로 다른 프로세스가 있을 때 프로세스 A가 프로세스 B가 사용하는 메모리 주소에 접근하여 값을 변경하면 시스템이 다운되는 문제가 있었음
-> OS에서 각각의 프로세스에 가상 메모리를 제공
프로세스는 가상 메모리 주소에 접근할 때 페이지 테이블을 가지고 서로 독립적으로 격리된 물리 메모리 영역에 안전하게 접근하게 된다.

## 스레딩 
하나의 프로세스에 대해 여러개의 스레드를 만들어 연산을 수행하는 방식
Code, Data, Heap영역을 공유하고 스레드는 각각의 Stack을 가진다. 
![[Pasted image 20260711220047.png|176]]

파이썬의 경우 GIL 때문에 하나의 프로세스 내에서 여러 스레드를 만들더라도, 동시에(병렬로) CPU 연산을 할 수 있는 스레드는 단 하나로 제한된다. 
따라서 파이썬의 멀티스레딩은 진짜 병렬 연산이라기보다는, 주로 대기 시간이 많은 I/O 작업(네트워크, 디스크 읽기/쓰기)에서 효율적인 컨텍스트 스위칭을 통해 동시성(Concurrency)을 구현하는 용도로 사용됨. (대규모 CPU 연산이 필요할 때는 GIL을 우회하는 멀티프로세싱이나 C 기반 라이브러리를 사용함.)

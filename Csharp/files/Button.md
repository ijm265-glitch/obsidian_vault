## 1. 개요 (Overview)
- **설명**: 사용자가 마우스로 클릭하거나 키보드로 엔터/스페이스바를 눌렀을 때 특정 동작(이벤트)을 실행하는 가장 기본적인 실행 명령 컨트롤입니다.
- **네임스페이스 / 클래스**: `System.Windows.Forms.Button` (상위 클래스: `ButtonBase` $\rightarrow$ `Control`)
- **역할**: 데이터 제출, 창 닫기, 계산 실행, 모달 창 확인/취소 등 사용자의 명시적인 입력을 받아 이벤트를 처리합니다.

---
## 드래그 앤 드롭
### 1. `DragEnter`
- **발생 시점**: 사용자가 파일이나 데이터를 마우스로 끌고(Drag) **컨트롤 영역 안으로 마우스 커서가 진입하는 순간** 1회 발생합니다.
- **주요 역할**:
    - 끌고 들어온 데이터가 이 버튼에서 수용 가능한 형식(파일, 텍스트 등)인지 검사합니다.
    - `e.Effect = DragDropEffects.Copy`와 같이 지정하여 마우스 커서 모양을 '복사', '이동', '금지' 등으로 바꿔줍니다.
### 2. `DragOver'
- **발생 시점**: 데이터를 마우스로 쥔 채 **컨트롤 영역 내부에서 마우스를 움직이는 동안** 지속적으로(연속해서) 발생합니다.
- **주요 역할**:
    - 마우스의 현재 위치 좌표에 따라 UI 피드백을 실시간으로 업데이트할 때 사용합니다. (예: 특정 위치에 마우스가 왔을 때 하이라이트 효과 부여)
### 3. `DragLeave`
- **발생 시점**: 데이터를 드롭하지 않고, **마우스를 누른 채 컨트롤 영역 밖으로 빠져나가는 순간** 발생합니다.
- **주요 역할**:
    - `DragEnter`나 `DragOver`에서 변경했던 컨트롤의 배경색이나 시각적 피드백 효과를 원상복구(시각적 초기화)할 때 사용합니다.
### 4. `DragDrop`
- **발생 시점**: 마우스로 끌고 온 데이터를 컨트롤 위에서 **마우스 버튼을 떼어 놓는(Drop) 순간** 발생합니다.
- **주요 역할**:
    - **실제 데이터를 전달받아 처리하는 가장 핵심적인 이벤트**입니다.
    - 끌어다 놓은 파일 경로를 읽어오거나(`e.Data.GetData(DataFormats.FileDrop)`), 텍스트 데이터를 처리하는 로직을 이곳에 작성합니다.
### 5. `GiveFeedback`
- **발생 시점**: 드래그 앤 드롭 동작 중에 **드래그 원본(Drag Source)** 측에서 발생합니다.
- **주요 역할**:
    - 마우스 커서 모양을 기본 OS 커서 대신 개발자가 직접 만든 커스텀 마우스 커서(Icon/Cursor)로 바꾸고 싶을 때 사용합니다.
### 6. `QueryContinueDrag`
- **발생 시점**: 드래그 상태가 유지되는 동안 **키보드 상태(Esc, Shift, Ctrl 등)나 마우스 상태가 변경될 때** 발생합니다.
- **주요 역할**:
    - 사용자가 드래그 도중 `Esc` 키를 눌렀을 때 드래그 작업을 취소하거나, 마우스 클릭 상태를 감지하여 드래그 앤 드롭을 중단/계속할지 결정할 때 사용합니다.

## 데이터
### 1. `(DataBindings)`

- **구분**: 속성 (Property)
    
- **설명**: 컨트롤의 UI 속성(예: `Text`, `Tag`, `Value` 등)을 C# 코드의 **데이터 객체, 클래스 프로퍼티, 또는 DB(데이터베이스) 필드와 동적으로 연결**할 때 사용합니다.
    
- **활용**:
    
    - `+` 아이콘을 누르면 바인딩할 항목들이 열립니다.
        
    - 텍스트박스에 입력한 값이 C# 객체의 프로퍼티에 자동으로 반영되도록 연동할 때 설정합니다.
        

### 2. `CommandCanExecuteChanged`

- **구분**: 이벤트 (Event)
    
- **설명**: 이 컨트롤에 연결된 명령(`ICommand`)의 **실행 가능 상태(`CanExecute`)가 변경되었을 때** 발생합니다.
    
- **활용**:
    
    - MVVM 아키텍처 패턴을 사용할 때, 특정 조건에 따라 버튼을 클릭할 수 있는지 없는지(`True`/`False`)의 상태 변경을 감지하고 UI를 업데이트할 때 작동합니다.
        

### 3. `CommandChanged`

- **구분**: 이벤트 (Event)
    
- **설명**: 컨트롤에 할당되어 있는 **명령(`Command`) 객체 자체가 다른 객체로 교체되거나 변경되었을 때** 발생합니다.
    
- **활용**:
    
    - 런타임 중에 버튼이 실행해야 하는 바인딩 명령 자체가 새로운 동작으로 변경되는 상황을 감지할 때 사용합니다.
        

### 4. `CommandParameterChanged`

- **구분**: 이벤트 (Event)
    
- **설명**: 명령을 실행할 때 함께 전달하는 **매개변수 값(`CommandParameter`)이 변경되었을 때** 발생합니다.
    
- **활용**:
    
    - 버튼이 클릭될 때 전달받을 인자 데이터(Parameter)가 실시간으로 바뀔 때 이를 감지하여 처리합니다.
        

### 5. `DataContextChanged`

- **구분**: 이벤트 (Event)
    
- **설명**: 컨트롤의 데이터 주체인 **`DataContext`(데이터 맥락/뷰모델 객체)가 바뀔 때** 발생합니다.
    
- **활용**:
    
    - 해당 UI 요소에 연결되어 있던 데이터 모델(ViewModel)이 새로 교체되거나 초기화될 때, 화면 갱신이나 추가 데이터 로딩 로직을 수행하는 용도로 쓰입니다.

## 동작
### 1. `ChangeUICues`

- **발생 시점**: 포커스 표시선(키보드 탭으로 이동 시 보이는 밑줄이나 점선)이나 단축키 안내 표시 등 **UI의 힌트/단서(Cues) 상태가 바뀔 때** 발생합니다.
    
- **주요 역할**: 사용자가 `Alt` 키나 `Tab` 키를 눌러 화면 표시 힌트 상태가 전환될 때, 컨트롤의 자체적인 렌더링 방식을 변경하는 용도로 쓰입니다.
    

### 2. `ControlAdded`

- **발생 시점**: 해당 컨트롤(또는 폼/패널)의 **내부에 새로운 자식 컨트롤이 추가될 때** 발생합니다.
    
- **주요 역할**: Panel, GroupBox, Form 같은 컨테이너 컨트롤에 런타임으로 새로운 버튼이나 텍스트박스가 들어오는 순간을 감지하여 자동 정렬이나 레이아웃 재배치 로직을 실행할 때 사용합니다.
    

### 3. `ControlRemoved`

- **발생 시점**: 해당 컨트롤 내부에 있던 **자식 컨트롤이 제거(삭제)될 때** 발생합니다.
    
- **주요 역할**: 컨테이너 요소에서 특정 부품 컨트롤이 삭제되었을 때 남은 요소들의 위치를 다시 계산하거나 메모리를 정리하는 로직을 작성합니다.
    

### 4. `HelpRequested`

- **발생 시점**: 사용자가 컨트롤을 선택한 상태에서 **`F1` 키를 누르거나, 타이틀바의 도움말 버튼(? 모양)을 클릭한 후 이 컨트롤을 눌렀을 때** 발생합니다.
    
- **주요 역할**: 특정 컨트롤 전용 팝업 도움말(HelpProvider)을 띄우거나, 연동된 매뉴얼 문서를 열어주는 기능을 구현할 때 사용합니다.
    

### 5. `QueryAccessibilityHelp`

- **발생 시점**: 보조공학 기기(화면 읽기 프로그램, 내레이터 등)가 이 컨트롤에 대한 **접근성 도움말 정보를 요청할 때** 발생합니다.
    
- **주요 역할**: 시각장애인용 내레이터 프로그램 등에 더 구체적이고 정교한 도움말 메시지를 동적으로 반환하고자 할 때 활용합니다.
    

### 6. `StyleChanged`

- **발생 시점**: 컨트롤의 **윈도우 스타일(OS 레벨의 컨트롤 스타일 플래그)이 변경될 때** 발생합니다.
    
- **주요 역할**: 컨트롤의 비주얼 스타일이나 Win32 윈도우 스타일 특성이 바뀔 때 그래픽이나 테마 관련 상태를 동기화할 때 작동합니다.
    

### 7. `SystemColorsChanged`

- **발생 시점**: 사용자가 윈도우 OS 설정에서 **시스템 테마 색상(예: 다크 모드/라이트 모드 전환, 고대비 설정 등)을 변경할 때** 발생합니다.
    
- **주요 역할**: OS 색상이 바뀌는 순간을 감지해서, 내가 만든 커스텀 컨트롤의 배경색이나 글자색을 윈도우 테마에 맞추어 실시간으로 바꿔줄 때 사용합니다.

## 레이아웃

### 1. `DpiChangedAfterParent`

- **발생 시점**: 부모 컨트롤(예: Form이나 Panel)의 DPI(해상도 배율)가 변경된 **후에** 이 자식 컨트롤의 DPI가 변경될 때 발생합니다.
    
- **주요 역할**: 고해상도 모니터 간 이동(4K $\leftrightarrow$ FHD)이나 OS 텍스트 배율 변경 시, 부모 레이아웃 조정이 완료된 후 자식 컨트롤의 폰트나 크기를 추가로 미세 조정할 때 쓰입니다.
    

### 2. `DpiChangedBeforeParent`

- **발생 시점**: 부모 컨트롤의 DPI가 변경되기 **전에** 이 컨트롤의 DPI 변경 처리가 먼저 일어날 때 발생합니다.
    
- **주요 역할**: 부모 요소의 크기 배율이 바뀌기 전에 자식 컨트롤 자체의 특수한 크기 계산 로직이나 그래픽 리소스를 미리 준비할 때 사용합니다.
    

### 3. `Layout`

- **발생 시점**: 컨트롤의 내부 레이아웃(자식 컨트롤들의 위치, 크기, 정렬 등)을 **다시 계산해서 배치해야 할 때** 발생합니다.
    
- **주요 역할**: 폼이나 패널 크기가 바뀔 때 그 안의 자식 버튼/텍스트박스들을 코드로 직접 수동 계산하여 배치(Custom Auto-Layout)하고 싶을 때 핵심적으로 사용합니다.
    

### 4. `MarginChanged`

- **발생 시점**: 컨트롤의 외부 여백을 나타내는 **`Margin` 속성 값이 변경될 때** 발생합니다.
    
- **주요 역할**: 다른 컨트롤과의 간격(외부 여백)이 바뀔 때 그에 맞춰 인접한 컨트롤들의 위치를 동적으로 조정하는 용도로 쓰입니다.
    

### 5. `Move`

- **발생 시점**: 컨트롤의 위치 좌표(`Location`, 즉 X/Y 값)가 **화면상에서 이동했을 때** 발생합니다.
    
- **주요 역할**: 마우스로 창을 드래그해서 옮기거나 코드로 `Location`을 바꿨을 때, 해당 좌표 변경을 감지하여 다른 팝업 창이나 툴팁 위치를 따라 이동시킬 때 활용합니다.
    

### 6. `PaddingChanged`

- **발생 시점**: 컨트롤 테두리와 내부 콘텐츠 사이의 여백을 나타내는 **`Padding` 속성 값이 변경될 때** 발생합니다.
    
- **주요 역할**: 컨트롤 안쪽 여백(내부 여백)이 바뀔 때 내부 텍스트나 자식 요소의 배치를 다시 계산할 때 사용합니다.
    

### 7. `Resize`

- **발생 시점**: 컨트롤의 **크기(`Size`, `Width`, `Height`)가 변경될 때** 발생합니다. _(매우 자주 쓰임!)_
    
- **주요 역할**:
    
    - 사용자가 마우스로 창 크기를 늘리거나 줄일 때 발생하는 가장 대표적인 이벤트입니다.
        
    - 창 크기에 맞춰 내부 UI 부품들의 크기나 위치를 비율에 맞게 늘리고 줄일 때 작성합니다.

## 마우스
### 1. `MouseDown`

- **발생 시점**: 컨트롤 영역 위에서 **마우스 버튼(좌/우/휠 등)을 누르는(클릭하는) 순간** 즉시 발생합니다.
    
- **주요 역할**:
    
    - 단순히 클릭을 떼는 것까지 기다리지 않고, 버튼이 눌려진 바로 그 순간 동작을 시작해야 할 때 사용합니다.
        
    - 전달되는 `MouseEventArgs e`를 통해 어떤 마우스 버튼(`e.Button == MouseButtons.Left/Right`)이 눌렸는지, 눌린 X/Y 좌표는 어디인지 정확히 알 수 있습니다.
        

### 2. `MouseEnter`

- **발생 시점**: 마우스 커서가 **컨트롤 영역 내부로 들어가는 순간** 1회 발생합니다.
    
- **주요 역할**:
    
    - 마우스가 올라왔을 때 버튼의 색상을 바꾸거나 아이콘을 확대하는 등 **호버(Hover) 피드백 효과**를 줄 때 사용합니다.
        

### 3. `MouseHover`

- **발생 시점**: 마우스 커서가 컨트롤 영역에 들어온 뒤, 움직이지 않고 **일정 시간 동안 가만히 머물러 있을 때** 발생합니다.
    
- **주요 역할**:
    
    - 마우스를 올리고 잠깐 기다렸을 때 툴팁(도움말 창)을 띄우거나 세부 정보 팝업을 보여주는 용도로 사용합니다.
        

### 4. `MouseLeave`

- **발생 시점**: 마우스 커서가 **컨트롤 영역 밖으로 빠져나가는 순간** 1회 발생합니다.
    
- **주요 역할**:
    
    - `MouseEnter`나 `MouseHover`에서 변경했던 버튼의 색상, 모양, 툴팁 등을 원래 상태로 **초기화**할 때 사용합니다.
        

### 5. `MouseMove`

- **발생 시점**: 마우스 커서가 **컨트롤 영역 안에서 움직이는 동안** 계속해서 반복해서 발생합니다.
    
- **주요 역할**:
    
    - 마우스의 실시간 X, Y 좌표를 추적할 때 사용합니다.
        
    - 컨트롤을 마우스로 드래그해서 위치를 이동시키거나, 그림판 앱처럼 마우스 궤적에 따라 선을 그릴 때 핵심적으로 쓰입니다.
        

### 6. `MouseUp`

- **발생 시점**: 눌렀던 **마우스 버튼을 떼는(올려놓는) 순간** 발생합니다.
    
- **주요 역할**:
    
    - 드래그 이동을 마칠 때, 또는 마우스 클릭 동작이 완성된 시점에 실행할 로직을 작성합니다.
        

### 7. `Paint`

- **발생 시점**: 컨트롤의 화면을 **새로 그려야 할 때(화면 갱신 시)** 발생합니다. _(WinForms 그래픽 제어의 핵심!)_
    
- **주요 역할**:
    
    - 폼이나 버튼에 원하는 도형(선, 원, 사각형), 커스텀 텍스트, 비트맵 이미지 등을 GDI+(`Graphics` 객체)로 직접 그리고 싶을 때 사용합니다.
        
    - `e.Graphics.DrawLine(...)` 또는 `e.Graphics.DrawString(...)` 형태로 커스텀 UI를 그릴 수 있습니다.

## 속성 변경 

### 1. 외관 및 스타일 변경 이벤트 (Appearance)

- **`BackColorChanged`**: 컨트롤의 배경색(`BackColor`)이 변경될 때 발생합니다.
    
- **`BackgroundImageChanged`**: 배경 이미지(`BackgroundImage`)가 새로 지정되거나 삭제될 때 발생합니다.
    
- **`BackgroundImageLayoutChanged`**: 배경 이미지의 레이아웃 배치 방식(`Tile`, `Stretch`, `Zoom` 등)이 바뀌었을 때 발생합니다.
    
- **`FontChanged`**: 글꼴 스타일이나 크기(`Font`)가 변경될 때 발생합니다.
    
- **`ForeColorChanged`**: 글자 색상(`ForeColor`)이 변경될 때 발생합니다.
    

### 2. 크기 및 위치/레이아웃 변경 이벤트 (Layout & Bounds)

- **`AutoSizeChanged`**: `AutoSize` 속성(내용에 따라 자동 크기 조절) 값이 `True`/`False`로 바뀔 때 발생합니다.
    
- **`ClientSizeChanged`**: 컨트롤 테두리를 제외한 실제 작업 영역(클라이언트 영역)의 크기가 바뀌었을 때 발생합니다.
    
- **`DockChanged`**: `Dock` 속성(상단, 하단, 채우기 등 부모 컨트롤 고정 위치)이 변경될 때 발생합니다.
    
- **`LocationChanged`**: 컨트롤의 X, Y 위치 좌표(`Location`)가 변경될 때 발생합니다.
    
- **`RegionChanged`**: 컨트롤의 그래픽 창 영역(`Region`, 예: 사각형이 아닌 원형 버튼 영역 등)이 수정될 때 발생합니다.
    
- **`SizeChanged`**: 컨트롤의 너비나 높이(`Size`)가 변경될 때 발생합니다.
    

### 3. 상태 및 동작 변경 이벤트 (State & Behavior)

- **`CausesValidationChanged`**: `CausesValidation` 속성(유효성 검사 수행 여부) 값이 변경될 때 발생합니다.
    
- **`EnabledChanged`**: 컨트롤의 활성화/비활성화 상태(`Enabled`, `true`/`false`)가 바뀔 때 발생합니다. (예: 버튼이 비활성화되는 순간 배경색을 바뀌게 처리하는 등)
    
- **`ParentChanged`**: 해당 컨트롤이 들어있는 부모 컨테이너(Form, Panel 등)가 다른 부모로 바뀌거나 제거될 때 발생합니다.
    
- **`RightToLeftChanged`**: 아랍어 등 우측에서 좌측으로 읽는 텍스트 정렬 모드(`RightToLeft`) 상태가 변경될 때 발생합니다.
    
- **`VisibleChanged`**: 컨트롤이 숨겨지거나 다시 나타날 때(`Visible`, `true`/`false`) 발생합니다.
    

### 4. 입력 및 포커스 / 데이터 변경 이벤트 (Input & Data)

- **`BindingContextChanged`**: 데이터 바인딩을 관리하는 `BindingContext` 객체가 변경될 때 발생합니다.
    
- **`ContextMenuStripChanged`**: 마우스 우클릭 시 뜨는 팝업 메뉴(`ContextMenuStrip`)가 변경될 때 발생합니다.
    
- **`CursorChanged`**: 마우스 포인터 모양(`Cursor`) 속성이 변경될 때 발생합니다.
    
- **`TabIndexChanged`**: `Tab` 키 이동 순서 번호(`TabIndex`)가 변경될 때 발생합니다.
    
- **`TabStopChanged`**: `Tab` 키를 눌렀을 때 포커스가 들어올지 여부(`TabStop`)가 변경될 때 발생합니다.
    
- **`TextChanged`** _(★ 가장 자주 쓰임)_: 컨트롤의 `Text` 속성(글자)이 변경될 때 발생합니다.
    
    - _Tip_: `TextBox`에서는 글자를 입력할 때마다 실시간으로 작동하며, `Button`이나 `Label`에서는 표기 텍스트가 바뀔 때 발생합니다.

## 1. 작업 (Action)

### 1. `Click` _(★ Button 최상위 중요 이벤트)_

- **발생 시점**: 사용자가 버튼을 클릭하거나, 키보드의 `Enter` / `Spacebar`를 눌러 버튼을 실행할 때 발생합니다.
    
- **주요 역할**: 버튼 눌림에 대한 메인 동작(데이터 저장, 창 열기, 계산 등)을 처리하는 로직을 작성합니다.
    

### 2. `MouseCaptureChanged`

- **발생 시점**: 이 컨트롤이 **마우스 캡처(Mouse Capture) 권한을 얻거나 잃었을 때** 발생합니다.
    
- **주요 역할**: 마우스를 누른 채 창 밖으로 나가는 등 마우스 입력 독점 상태가 해제될 때 UI 상태를 초기화할 때 사용합니다.
    

### 3. `MouseClick`

- **발생 시점**: 마우스로 컨트롤을 클릭할 때 발생하며, `Click`과 달리 `MouseEventArgs`를 전달받습니다.
    
- **주요 역할**: 클릭된 마우스 버튼이 **좌클릭인지 우클릭인지(`e.Button`)**, 클릭된 X, Y 좌표(`e.Location`)가 어디인지 구분해서 처리할 때 사용합니다.
    

## 2. 키 (Key) - 키보드 입력

### 1. `KeyDown`

- **발생 시점**: 키보드의 **키를 누르는 순간** 즉시 발생합니다.
    
- **주요 역할**: `Ctrl`, `Alt`, `Shift`, `F1~F12`, `Arrow` 등 모든 특수키를 포함한 키 입력을 감지할 때 주로 쓰입니다.
    

### 2. `KeyPress`

- **발생 시점**: 문자가 입력될 때(`KeyDown` 직후) 발생합니다.
    
- **주요 역할**: 실제 **문자(ASCII/Unicode) 값**을 처리할 때 쓰이며, 텍스트박스에서 숫자만 입력받도록 제어할 때(`e.Handled = true`) 핵심적으로 사용됩니다.
    

### 3. `KeyUp`

- **발생 시점**: 눌렀던 **키보드 키에서 손을 떼는 순간** 발생합니다.
    
- **주요 역할**: 키 조합 입력 종료 시점 감지나 키 누름 상태 초기화에 사용됩니다.
    

### 4. `PreviewKeyDown`

- **발생 시점**: `KeyDown` 이벤트가 발생하기 **직전**에 먼저 발생합니다.
    
- **주요 역할**: `Tab`, `Enter`, 방향키 등 기본적으로 UI 포커스 이동에 쓰이는 키들을 컨트롤이 직접 이벤트로 가로채서 처리하고 싶을 때(`e.IsInputKey = true`) 사용합니다.
    

## 3. 포커스 (Focus) - 입력 대상 전환

### 1. `Enter`

- **발생 시점**: 마우스 클릭이나 `Tab` 키 이동을 통해 **포커스(Focus)가 이 컨트롤로 들어올 때** 발생합니다.
    
- **주요 역할**: 컨트롤이 선택되었을 때 테두리 색상을 바꾸거나 안내 문구를 출력할 때 사용합니다.
    

### 2. `Leave`

- **발생 시점**: 포커스가 이 컨트롤을 벗어나 **다른 컨트롤로 이동할 때** 발생합니다.
    
- **주요 역할**: 포커스가 나가는 순간 UI 하이라이트를 해제하거나 입력 데이터를 1차 확인합니다.
    

### 3. `Validating`

- **발생 시점**: 포커스가 벗어나기 직전, **입력된 데이터의 유효성을 검사할 때** 발생합니다.
    
- **주요 역할**: 빈칸 검사나 정규식 검사를 수행하며, 잘못된 값이면 `e.Cancel = true`로 포커스가 밖으로 나가지 못하게 막습니다. _(단, `CausesValidation = True`일 때 작동)_
    

### 4. `Validated`

- **발생 시점**: `Validating` 이벤트의 검사를 **오류 없이 무사히 통과한 직후** 발생합니다.
    
- **주요 역할**: 검증이 완료된 데이터를 변수에 저장하거나 폼 상태를 갱신할 때 활용합니다.

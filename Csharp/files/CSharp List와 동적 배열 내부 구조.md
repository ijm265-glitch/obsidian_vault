## `List<T>`의 핵심 내부 필드
 `List<T>`의 내부 소스 코드를 들여다보면 핵심적으로 두 가지 필드를 관리합니다.
```cs
public class List<T>
{
    private T[] _items; // 실제 데이터를 담는 내부 연속 배열
    private int _size;  // 현재 리스트에 들어있는 실제 요소 개수 (Count)
    
    // ...
}
```

- **Capacity (용량):** 내부 배열 `_items.Length`의 크기. (현재 메모리에 할당된 총 공간)
- **Count (개수):** 실제 사용자가 리스트에 넣은 데이터 개수 (`_size`).

## 연산별 시간 복잡도 (Time Complexity)

| **연산 (Operation)**                 | **시간 복잡도**           | **설명**                              |
| ---------------------------------- | -------------------- | ----------------------------------- |
| **인덱스 접근 (`list[i]`)**             | **$O(1)$**           | 연속된 메모리 주소이므로 즉시 접근 가능              |
| **끝에 추가 (`Add`)**                  | **$O(1)$** _(분할 상한)_ | 기본적으로 $O(1)$이나, **재할당 발생 시 $O(N)$** |
| **중간 삽입/삭제 (`Insert`/`RemoveAt`)** | **$O(N)$**           | 지정 위치 이후의 모든 요소를 **한 칸씩 밀거나 당겨야 함** |
| **값 검색 (`Contains`/`IndexOf`)**    | **$O(N)$**           | 처음부터 끝까지 순차 탐색 (선형 탐색)              |
### ① `Capacity` 미리 지정하기 (가장 중요!)

요소 개수를 어느 정도 예측할 수 있다면, 생성자에서 미리 `Capacity`를 지정하는 것이 성능상 매우 유리합니다. **배열 재할당 및 데이터 복사 오버헤드와 GC 부하를 크게 줄일 수 있습니다.**

```cs
// ❌ 비효율적: 10,000번 추가하는 동안 수많은 배열 재할당과 메모리 복사 발생
List<int> list = new List<int>();
for (int i = 0; i < 10000; i++) list.Add(i);

// ⭕ 효율적: 10,000개 공간을 한 번에 할당하여 재할당 오버헤드 0
List<int> list = new List<int>(10000);
for (int i = 0; i < 10000; i++) list.Add(i);
```
## 1. 인덱스 접근 (`list[i]`)

- **설명:** 배열처럼 대괄호`[]` 안에 위치 번호(인덱스)를 지정해서 해당 위치의 값을 바로 가져오거나 새로운 값을 대입합니다.
- **시간 복잡도:** **$O(1)$** (최상)
- **내부 동작:** `List<T>`는 내부 데이터가 연속된 메모리 공간(배열)에 놓여 있습니다. 따라서 `시작 주소 + (인덱스 × 데이터 크기)`라는 단순한 수학 계산으로 복잡한 탐색 없이 메모리에 즉시 접근합니다.
```cs
List<string> names = new List<string> { "Alice", "Bob", "Charlie" };

string item = names[1]; // "Bob"을 즉시 가져옴
names[0] = "Alex";      // 0번 자리를 "Alex"로 덮어씀
```

## 2. 끝에 추가 (`Add`)

- **설명:** 리스트의 **맨 마지막 자리에 새로운 요소를 하나 덧붙입니다.**    
- **시간 복잡도:** **평균 $O(1)$** (단, 공간 부족으로 용량(Capacity)을 2배로 늘릴 때는 $O(N)$)
- **내부 동작:**
    1. 남은 공간(`Capacity`)이 있다면 맨 끝 위치(`Count`)에 값을 집어넣고 `Count`를 +1 올립니다.
    2. 공간이 모자라면 기존 배열의 2배 크기로 새 배열을 만든 뒤 기존 값을 복사해 오고 나서 맨 뒤에 추가합니다.
```cs
List<int> numbers = new List<int> { 10, 20 };

numbers.Add(30); // [10, 20, 30] 이 됨
```

## 3. 중간 삽입 / 삭제 (`Insert` / `RemoveAt`)

- **설명:**    
    - `Insert(index, item)`: 지정한 인덱스 위치에 새로운 값을 **끼워 넣습니다.**
    - `RemoveAt(index)`: 지정한 인덱스 위치의 값을 **삭제합니다.**
- **시간 복잡도:** **$O(N)$** (느림)
- **내부 동작:** 연속된 메모리 특징 때문에 중간 자리가 비거나 새 데이터가 들어오면 **뒤에 있는 모든 데이터들을 한 칸씩 뒤로 밀거나(`Insert`) 앞으로 당겨야(`RemoveAt`) 합니다.**

```cs
List<string> alphabet = new List<string> { "A", "C", "D" };

// 1번 자리에 "B" 삽입 -> 뒤에 있던 "C", "D"가 한 칸씩 뒤로 밀림
alphabet.Insert(1, "B"); // ["A", "B", "C", "D"]

// 2번 자리("C") 삭제 -> 뒤에 있던 "D"가 한 칸 앞으로 당겨짐
alphabet.RemoveAt(2);   // ["A", "B", "D"]
```

## 4. 값 검색 (`Contains` / `IndexOf`)

- **설명:**
    - `Contains(item)`: 특정 값이 리스트 안에 존재하는지 여부(true/false)를 반환합니다.
    - `IndexOf(item)`: 특정 값이 **몇 번 인덱스에 위치해 있는지** 번호를 반환합니다. (없으면 `-1` 반환)
- **시간 복잡도:** **$O(N)$** (느림)
- **내부 동작:** 리스트는 키(Key)나 규칙 없이 데이터가 순서대로 적재되어 있으므로, 원하는 값을 찾을 때까지 0번 인덱스부터 맨 끝까지 순차적으로 하나씩 비교(선형 탐색)합니다.

```cs
List<int> scores = new List<int> { 80, 95, 70, 100 };

bool hasHundred = scores.Contains(100); // true (0번부터 탐색하다가 100을 찾음)
int index70 = scores.IndexOf(70);       // 2 (70이 2번 인덱스에 있다고
```
